# 아바타 뷰어 로딩 성능 검증

2026-10-24, 실제 `results`와 설치된 게임 원본을 사용했다. 게임 원본과 기존 추출 에셋을 수정하거나 삭제하지 않았다. 파생 캐시만 생성·갱신했다. 시작 시 작업 트리는 깨끗했고 Python/Node 분석 작업과 8765 리스너는 없었다. 이후 직접 시작한 서버만 포트 소유자·실행 명령·작업 유휴 상태를 재확인하고 재시작했다.

## 재사용과 무효화

- **작업 경계:** 중첩 가능한 `Catalog.session()`이 연결을 한 작업에 공유한다. `GameNames.session()`은 thread-local 경계이며 다음 작업에서 원본을 다시 확인한다. 영구 신뢰나 시간 기반 TTL을 추가하지 않았다. 실패 시에도 연결과 세션 상태를 정리한다.
- **후보 조회:** 모델 작업 동안 대소문자를 정규화한 정확한 파일명으로만 재사용한다. 모든 출처와 중복·누락 안내 및 소유 아카이브 우선순위를 유지한다. 다음 작업에서는 다시 조회한다.
- **모델·동작:** 원본 읽기·앞뒤 검증·SHA-256 계산 이후 중립 파싱 결과만 재사용한다. 키는 형식·내용 해시·선택 클립이다. 32 MiB/32개 LRU이며 초과 결과는 보관하지 않는다. 매번 깊은 복사본을 반환한다. 최종 scene·아이템 외형·재질·장비 숨김·눈동자 결과를 캐시하지 않으므로 선택한 아이템과 타입별 XET가 다른 결과에 섞이지 않는다. 공용 뼈도 실제 내용으로 구분한다. 기존 LoadingCache의 카탈로그 개정·NTF/LUA/XET/CW.EXE 의존성 검증은 유지한다.
- **이미지 준비:** 최대 128개의 메타데이터만 보관한다. 요청마다 카탈로그 개정/DB 정체성, 전체 항목 정보, 실제 저장 파일 또는 CMF의 크기·mtime·inode, 파생 출력 상태를 확인한다. 원본 CMF가 목록과 다르면 오류를 유지한다. 손상된 파생 파일은 원본에서 복구한다. 기존 디스크 상한 256 MiB와 입력 64 MiB/16,777,216픽셀 제한은 유지한다.
- **GPU 텍스처:** 출처 ID·이미지 SHA-256·기본색/발광 역할을 키로 쓴다. 사용 모델의 참조와 보관 캐시의 소유권을 구분한다. 최대 세 작업을 동시에 준비하며 pending 이미지도 픽셀 예산에 예약한다. 총 33,554,432픽셀/64개를 넘으면 참조가 없는 항목부터 퇴출한다. 사용 중인 항목을 해제하지 않는다. 다시 열 때도 서버 메타데이터를 재검증하고, 유효한 GPU 텍스처는 다시 업로드하지 않는다. 모델 교체 시 형상·재질·스켈레톤·확장 스킨 텍스처를 해제하고 이미지 참조를 반환한다. 페이지 종료 시 남은 캐시와 진행 중 결과까지 정리한다.
- **요청 경합:** 모델 세대 번호와 AbortController, 별도 동작·클립 버전으로 오래된 응답을 차단한다. 텍스처 완료 후에도 모델 소유자를 확인한다. 오래된 finally 블록이 최신 로딩 표시를 지우지 않는다. 초기화·종료 후 동작 응답이 모델을 복구하지 않는다.

## 모델 교체·후처리 종료 추가 검증 (2026-11-02)

`test_model_postprocess_lifecycle_browser.py`는 실제 `model.js`·애니메이션 루프·GPU 업로드와 후처리를 실행하고, 모델 응답 및 텍스처 디코딩 완료 시점을 제어한다. 1×1 텍스처의 디코딩만 대기 가능한 테스트 로더로 바꾸므로 실제 이미지 파일 디코딩 성능이나 게임 모델 표시 시간을 재측정한 검사는 아니다.

- 색상 보정·선명도·심도·5단계 번짐을 선택한 상태로 발광 모델과 일반 모델을 반복 교체해, 이전 재질의 한 번 해제·실제 출력 변경·GPU 텍스처 참조 반환을 확인한다.
- 교체 실패 시 기존 후처리 프레임과 텍스처 참조를 유지하는지 검사한다. 취소 신호를 무시하고 뒤늦게 도착한 모델 응답도 최신 모델과 로딩 상태를 덮어쓰지 않아야 한다.
- 이전 모델의 디코딩을 교체 후에 완료해도 이미 해제된 재질에 텍스처가 연결되지 않고 캐시 참조가 0으로 반환되는지 확인한다.
- 디코딩 중 페이지 종료, 늦은 디코딩 완료, 종료 후 새 모델 요청, 이미 큐에 있던 크기 변경 콜백과 반복 종료를 검사한다. 모델·캐시·로딩 표시를 정리하고 종료 뒤 WebGL 핸들 수가 늘지 않으며 설정 저장값을 유지해야 한다.

검사에서 종료 후에도 viewport의 `ResizeObserver`가 연결되어 있었고 새 모델 요청을 받아 닫힌 뷰어에 모델을 다시 만들 수 있었다. 이제 종료 시 감시자·알림 타이머·모델 요청·애니메이션 루프를 정리하고 작업/모델 버전을 무효화한다. 종료 처리는 한 번만 실행하고 이후 작업·로딩과 큐에 남은 크기 변경 콜백을 무시한다. 캐시 예산이나 메뉴·그래픽 계산식은 바꾸지 않는다.

## 보조 연출의 지연 로딩 취소 (2026-11-02)

`test_motion_extras_lifecycle_browser.py`에서 초기화 후 도착한 이미지 정보가 새 텍스처 디코딩을 시작하는 문제를 재현했다. 이미지 정보 요청 전후·디코더 시작/완료·캐시 반환 때 연출 버전과 취소·종료 상태를 확인하도록 수정했다. 취소 후 완료된 디코딩 결과는 캐시가 소유하기 전에 한 번 해제한다. 종료된 연출 관리자의 새 선택·갱신·오디오 활성화·버튼 재활성화를 막고 종료를 여러 번 호출해도 정리를 반복하지 않는다.

## 보조 모델의 후처리 가림 (2026-11-02)

아바타만 그리던 발광 마스크·DOF 깊이 패스가 앞쪽 보조 모델의 가림을 무시하는 문제를 재현했다. `model.js`가 현재 보조 메시를 후처리에 전달하고, `model-occlusion.js`가 일반 깊이 검사·기록을 사용하는 불투명 MeshBasicMaterial 보조 모델을 색상 기록 없이 먼저 그린다. 가려진 아바타 발광이 번짐에 남지 않고, 불투명 보조 모델 위에 뒤쪽 아바타의 DOF 영역이 기록되지 않는다. 텍스처 알파 테스트·형상·현재 변환은 기존 렌더 경로를 사용한다.

새 렌더 타깃이나 대체 재질을 만들지 않는다. 해당 보조 모델이 있고 발광 마스크 또는 DOF 깊이를 그리는 경우에만 깊이 선행 패스가 추가된다. 보조 모델 자체의 DOF 및 발광 재현을 확장한 것은 아니며 반투명·가산·깊이 미기록 재질은 불투명 가림에 포함하지 않는다. 추가 패스의 실제 게임 모델 성능은 별도 측정이 필요하다.

`test_auxiliary_occlusion_browser.py`는 MSAA 켜기/끄기 각각에서 앞·뒤 모델, 알파 테스트 구멍, 숨긴 모델, 반투명/깊이 미기록 모델, 가산 효과의 발광 마스크 제외, DOF 출력 보존과 예외 후 상태 복원을 확인한다. 번짐은 같은 HDR/MSAA 경로에서 완전히 가려진 아바타를 제거한 참조와 픽셀 단위로 비교한다. `test_model_postprocess_lifecycle_browser.py`는 실제 뷰어의 애니메이션 루프에서도 보조 메시가 깊이 패스에 연결되는지 확인한다. 통제된 형상·재질을 사용한 검사이며 게임 파티클 전체의 깊이/블렌딩 일치를 입증하지 않는다.
