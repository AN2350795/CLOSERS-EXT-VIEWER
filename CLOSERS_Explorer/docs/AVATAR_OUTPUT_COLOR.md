# 아바타 출력 색상 경로 조사 (2026-10-30)

일반 장치 생성 경로의 설정값부터 백버퍼 RTV 생성까지 추적했다. 이 경로는 `R8G8B8A8_UNORM`(28)을 지정한다. 감마 플래그의 기본값이 켜져 있다는 사실만으로 출력 RTV가 sRGB(29)라고 판단할 수 없다. 인게임 최종 화면 전체의 감마·후처리 재현은 아직 미완료다.

## 조사 대상과 재검사

대상은 로컬 `CW.EXE`, SHA256 `8ea0ce3ba885f3044103c8e071e627b52a0e93cf56cc44b0e03dffed7c440283`이다. 실행 파일과 원본 에셋을 변경하거나 게임을 실행하지 않았다.

```powershell
python tests/audit_output_color.py --exe 'C:/Program Files (x86)/NaddicGames/Closers/CW.EXE'
```

감사 도구는 SHA256과 아래 근거의 명령 바이트 10곳을 대조한다. 다른 버전의 실행 파일이면 주소를 적용하지 않고 실패한다. 이 검사는 기록한 근거가 그대로인지 확인하는 용도이며, 실행 중의 상태나 인게임 화면 일치를 검증하지 않는다.

## 출력 Format의 연결

| 위치 | 확인한 동작 |
| --- | --- |
| `0x1417b6475` | 기본 장치 설정 `+0x28`에 Format 28 지정 |
| `0x1417b6733` | 성공한 설정 검증 경로에서도 `+0x28`에 28 지정 |
| `0x14001906e~0x140019077` | 앱이 `0x140002410`을 설정 콜백으로 등록 |
| `0x140002410~0x14000243c` | 콜백은 조건부 별도 호출 후 true 반환. 입력 설정의 Format을 쓰지 않음 |
| `0x1417bf0e7~0x1417bf180` | 콜백 호출·설정 재검증 후 로컬 설정 128바이트를 현재 상태에 복사 |
| `0x1417bc979/0x1417bc99b` | 스왑체인 descriptor Format 28, CreateSwapChain 호출 |
| `0x1417bc2d9~0x1417bc33f` | 현재 상태 `+0x28`을 RTV descriptor Format에 복사하고 CreateRenderTargetView 호출 |
| `0x1417bd1db/0x1417bd8ee` | 초기 생성·크기 변경에서 같은 RTV 생성 함수를 호출 |

RTV 생성 함수 `0x1417bc250`은 상태 `+0x497`의 감마 플래그나 형식 변환 함수 `0x1417c6790`을 직접 사용하지 않는다. 따라서 확인한 일반 생성 경로의 RTV에는 추가 하드웨어 sRGB 쓰기 변환을 지정하지 않는다. 모든 장면의 최종 출력이 이 RTV를 그대로 사용한다는 뜻으로 확대하지 않는다.

## 감마 플래그와 오탐 구분

상태 생성자 `0x1417af2bd`는 `+0x497`을 1로 초기화한다. getter `0x1417b8300`과 변환 함수 `0x1417c6790`은 별도로 존재한다. 이 변환 함수는 플래그가 켜져 있으면 28을 29로 바꾸며, 텍스처·UI 관련 경로에서 실제 호출도 확인했다. 이 사실은 아바타 백버퍼 RTV의 Format 변환 근거가 아니다.

변위 바이트 검색에서 감마 setter의 참조처럼 보였던 `0x14171f75b`는 명령 경계로 디코딩하면 `0x14171f75a: call 0x140005c40`의 일부였다. 실제 감마 setter 호출로 취급하지 않는다. 플래그가 앱에 의해 꺼진다는 근거도 확보하지 못했다. 포인터를 통한 호출 가능성 역시 직접 호출 검색만으로 배제할 수 없다.

## 후처리: 확인한 순서와 남은 연결

`NKDGDOF::m_pColorGradingRenderTarget` 이름으로 생성한 리소스는 `0x141575299~0x1415752f2`에서 객체 `+0x2a8`에 보관된다. 패스 연결 함수 `0x141575fe0`은 객체 `+0x290`의 비트에 따라 다음 호출을 수행한다.

| 순서 | 함수 | 호출 조건 |
| --- | --- | --- |
| 1 | `0x141572d60` | 연결 함수 진입 후 호출 |
| 2 | `0x1415722f0` | bit 6 |
| 3 | `0x1415716f0` | bit 2 |
| 4 | `0x141573950` | bit 4 |
| 5 | `0x141571f20` | bit 5 |

뒤 패스가 켜져 있으면 앞 패스의 출력에 중간 타깃을 사용한다. 예를 들어 bit 4와 bit 5가 함께 켜지면 네 번째 호출의 출력은 `+0x2a8`에 들어가고 다음 호출의 입력으로 전달된다. 리소스 이름만으로 네 번째 패스의 셰이더를 색상 보정이라고 단정하지 않는다. 다섯 번째 함수는 `0x141571fbf~0x141571fc4`에서 기법 번호 `0x10`을 선택한다. 기법 번호와 셰이더, 활성 비트의 설정 주체를 연결하는 작업이 남아 있다.

별도로 설정 파서는 `ColorGrading`, `m_v3ColorGrading_BCS`, `m_v3ColorGrading_RGB` 항목을 읽는다(`0x1406cb7cc~0x1406cb880`). 이 설정과 위 활성 비트·셰이더 상수의 연결, 지역·캐릭터 선택 시 실제 값은 미확정이다. 셰이더 파일의 존재나 지역의 HDR 관련 수치만으로 후처리 기본값을 만들지 않는다.

## 뷰어 반영 범위와 다음 작업

현재 **원본 형식의 색상 계산 비교 (후처리 미포함)**는 입력 UNORM 계산과 추가 sRGB 출력 변환 생략을 함께 비교한다. 이번 조사로 일반 RTV 생성 경로에 대한 근거를 보강했다. 기본은 계속 OFF이며 인게임 재현 옵션으로 이름을 바꾸지 않는다.

다음은 후처리의 활성 비트 설정과 기법 `0x10`의 셰이더·상수 연결을 확인하는 작업이다. 이후 동일 조건의 인게임 화면과 대조해야 기본 계산 변경 여부를 판단할 수 있다. 접선·얼굴 기준 축, 조명 자동 선택·거리·회전, EXT B 계수 연결도 남아 있다.
