# 모델·모션 분류와 실제 명칭

## 한 번의 추출로 적용

웹의 **추출 후 데이터 후처리**를 켠 상태에서 **분석하고 바로 추출** 또는 선택·검색 결과 추출을 실행한다. 원본 저장 뒤 다음 작업을 한 번씩 수행한다.

1. 게임 문자열·아이템·캐릭터 스킬·NPC 정의·스킨 패키지를 대조해 실제 명칭 인덱스를 만든다.
2. 기존 목록의 모델·모션 분류를 갱신하고 전체 작업 공간의 `model-catalog.json`을 만든다.

이미 추출한 데이터에는 **후처리만 실행**을 사용한다. 추출 필터 밖의 파일도 명칭 연결에 필요한 정의를 읽을 수 있도록 원본 CMF가 분석돼 있어야 한다. CW.EXE와 pycryptodome이 필요하며 게임 실행 파일은 읽기만 한다. `DAT/DAT0/*.CMF` 배치도 실행 파일 자동 탐색을 지원한다.

CLI의 `extract`와 `process`도 기본으로 같은 후처리를 실행한다.

```powershell
python CLOSERS_Explorer/explorer.py extract --category models --executable "C:/Program Files (x86)/NaddicGames/Closers/CW.EXE"
```

후처리를 생략하려면 `--no-postprocess`를 추가한다. `scan`은 목록 분석만 하며 후처리를 실행하지 않는다. `names`는 명칭 인덱스만 갱신하는 별도 명령이고 `motion-audit`는 기존 조사 도구다. 이 두 명령을 추출 통합 후처리와 혼동하지 않는다.

일반 **목록 CSV**에도 실제 명칭·모델 종류·캐릭터·부위·의상 분류 열을 추가했다. 원본 이름 열과 파일 경로는 보존한다. 이름 인덱스만 바뀐 경우에도 CSV를 다시 생성한다.

## 탐색

모델·의상·눈동자 목록을 불러올 때 **현재 처리 단계**, **현재 묶음의 처리 건수**, **경과 시간**, **마지막 진행 확인 시각**을 표시한다. 원본 확인·명칭 연결·저장 파일 확인·세트 구성 등 실제 서버 처리에서 진행 정보를 전송한다. 전체 개수를 모르는 캐시 읽기·대기 단계는 퍼센트를 만들지 않는다. 묶음별 건수는 해당 단계의 수치이며 전체 작업 진행률을 뜻하지 않는다.

진행 정보가 10초 이상 갱신되지 않으면 응답 지연 안내와 **다시 시도**를 표시한다. 시간만으로 서버 정지를 판정하지 않는다. **취소**는 현재 요청을 닫으며 서버는 다음 진행 확인 지점에서 중단한다. 캐시 파일 읽기·DB 조회처럼 한 번에 처리하는 구간은 그 구간이 끝나야 취소를 확인할 수 있다. 취소·오류 때 기존 목록을 유지하며 늦게 도착한 이전 결과는 적용하지 않는다.

목록 준비가 끝나면 아이콘의 별도 처리 건수를 표시한다. 이 건수는 화면 근처에서 요청한 아이콘 기준이며, 페이지 밖의 아직 요청하지 않은 이미지까지 포함하지 않는다. 아이콘을 불러오는 동안에도 목록을 탐색할 수 있다.

3D 뷰어의 **상세 필터 · 기록 → 원본 자료 탐색**에서 원본 자료 목록으로 전환한다. 종류 필터와 **자료 형식**을 함께 사용한다. 캐릭터를 비우면 다른 캐릭터·NPC·몬스터·배경 자료도 탐색할 수 있다.

- 종류: 아바타, 공용 뼈·동작, NPC, 몬스터, 펫, 배경·오브젝트, 효과, 카메라, 충돌·이동 영역, 장면 연출, Spine, 미분류.
- 형식: X, XMD, FBX, SKEL 등 현재 목록에 존재하는 형식.
- XMD는 X 모델처럼 열지 않고 **현재 모델에 동작 연결**로 뼈를 검증한다. FBX·SKEL 등은 이 목록에서 원본 저장을 제공한다. 목록에 포함됐다는 이유로 모든 형식의 3D 재생이 지원되는 것은 아니다.
- **모델·모션 전체 분류표 저장**으로 `model-catalog.json`을 내려받는다. 파일별 출처·원본 코드·분류·실제 명칭과 XMD의 클립별 명칭·등록·해석 오류를 확인할 수 있다. 미분류와 이름 없는 항목도 목록에서 제외하지 않는다.

동작 목록에서 스킬·이모션 명칭으로 검색할 수 있다. 스킨 패키지명은 `실제 스킨명 · 원본 클립 코드`로 표시한다. 패키지명은 개별 대기·이동 클립 자체의 공식 이름과 다르므로 `name_kind=context`로 구분한다. 전용 스킬·이모션 클립에 연결된 이름은 `name_kind=official`이다. 일반 점프·이동이나 다른 스킬의 모션을 재사용하는 연결은 `name_kind=reference`로 표시하고, 동작의 원본 코드를 유지하면서 연관 스킬명을 검색·정보에 제공한다. 동일 코드의 스킬 명칭이 있으면 재사용 스킬 명칭보다 우선한다.

## 연결 근거

| 대상 | 원본 연결 |
| --- | --- |
| 아바타·장비 | `ITEM_MODEL_TEMPLET*.NTF`의 아이템 번호·모델 → `ITEM_TEMPLET*.NTF` → `STRING_TABLE_ITEM*_KOREA.NTF` |
| 전투 스킬·이모션 | 공통 및 `SKILL_TEMPLET_<캐릭터>.LUA`의 스킬 ID·명시된 상태 → 상속된 캐릭터 상태의 `m_AnimName` → `ST_<스킬 ID>_NAME` |
| NPC·몬스터·펫 | `GUST_NPC_*.LUA`의 상속된 `m_Name`·`m_MotionFileName` → 해당 문자열과 정확한 모델 참조. 동명 XMD에도 소유 유닛 명칭을 연결 |
| 타운·던전 스킨 | `NEW_CONVERT_PACKAGE_TEMPLET.NTF`의 캐릭터·장면별 그룹·문자열 키 → 타운/던전 변환 테이블의 클립 등록 |
| 기본 분류 | 파일명 규칙과 형식. 명시적 유닛 참조가 있는 경우 원본 유닛 종류를 반영 |

캐릭터별 스킬 테이블은 해당 캐릭터에만 연결한다. 요구 조건의 상태를 스킬 재생 상태로 사용하지 않는다. 동일 이름의 서로 다른 유닛 정의, 상태·종류 충돌, 상속 순환은 임의로 확정하지 않는다. UI 문자열은 별도 이름 공간이므로 기본·캐릭터 문자열에 없는 키만 보충한다. 파일 이름 번역이나 유사한 세트·캐릭터 이름으로 실제 명칭을 만들어 넣지 않는다.

후처리는 명칭 인덱스와 분류표를 각각 임시 파일에 완성한 후 교체한다. 단계별 실패·중단은 추출 파일을 삭제하지 않는다. 명칭 연결에 실패한 개별 유닛 정의는 분류표의 `naming_warnings`와 후처리 결과에 남긴다. 모션 해석 오류와 뼈 검증 실패는 분류·원본 추출 성공과 별개다.
