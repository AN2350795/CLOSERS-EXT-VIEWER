# 파티클 깊이 기록과 심도 적용 근거

파티클은 원본 정의에서 정규화한 깊이 검사·쓰기와 RGB 블렌딩 설정을 사용한다. 2026-11-03 일반 알파 블렌딩의 3D 평면 파티클을 수동 DOF의 깊이 입력에 연결했다. 적용 조건과 원본과의 차이는 아래 구현 항목에 기록한다. 하드웨어 깊이 버퍼 기록과 DOF가 읽는 색상 MRT2 출력은 별개이며, 두 경로를 같은 플래그로 켜지 않는다.

## 원본에서 확인한 출력

설치 아카이브의 DXBC를 Windows `D3DDisassemble`로 읽었다. 게임·Lua·원본 셰이더를 실행하지 않았다. 재검증 도구 `tests/audit_particle_depth.py`는 원본 파일 해시와 DXBC 출력 시그니처를 확인한다.

| 셰이더 | 출력 시그니처 | 확인한 범위 |
| --- | --- | --- |
| `CW_QUAD.PS.CSO` | SV_Target 0·1·2 | `v3.z`, `CBPerGlobal[8]`로 기존 DOF와 같은 초점 기준 깊이를 MRT2 RGB에 기록 |
| `CW_NOLIGHT.PS.CSO` | SV_Target 0·1·2 | `v6.z`, `CBPerGlobal[8]`로 같은 깊이 수식을 사용 |
| `CW_SIMPLE.PS.CSO` | SV_Target 0 | 이 셰이더의 출력 시그니처에는 MRT2가 없음 |

QUAD는 `cb6[0].y == 1`, NOLIGHT는 `cb5[19].y == 1` 조건에 따라 MRT2 알파를 표면 알파 또는 표면 알파×최종 색 R로 선택한다. QUAD에는 저알파 색상을 0으로 만드는 경로와 별도 dissolve discard도 있다. 따라서 MRT2에 깊이 수식을 출력한다는 사실만으로 커버리지 알파를 1로 정하거나 하드웨어 깊이 기록 여부를 결정할 수 없다. 출력 시그니처 역시 실행 중 해당 타깃이 연결되고 쓰기 마스크가 켜져 있다는 증거는 아니다.

일반 3D 평면 파티클의 선택 경로와 상태 생성은 아래 추가 조사에서 연결했다. 마스크·메시·Spine/FBX 및 다른 draw 경로, 실제 실행 중의 타깃 연결·상수 덮어쓰기는 아직 남아 있다. `SIMPLE`을 포함한 모든 파티클이 DOF에 참여한다거나, QUAD의 모든 draw가 MRT2를 갱신한다고 결론 내리지 않는다.

## 일반 3D 평면의 상태 전달 추가 조사 (2026-11-03)

`tests/audit_particle_render_state.py`는 설치 `CW.EXE`의 지문과 명령 바이트 **38곳**, 두 공유 플래그의 PE 초기 상태·상수 버퍼 주소 연결을 확인한다. 분석에 사용한 디스어셈블러는 게임 파일을 읽기만 하며, 재검증 도구는 별도 디스어셈블러 설치 없이 실행할 수 있다.

| 연결 | 확인한 주소와 내용 |
| --- | --- |
| 종류 | `0x14185d09c`부터 PCT_3D_PLANE=0, PCT_2D_PLANE=1, PCT_MESH=2 등록. 로더는 `+0x94`에 저장 |
| 깊이 플래그 | `0x1415c17d9`에서 검사/쓰기를 템플릿 `+0x354/+0x355`에 읽음 |
| 깊이 전달 | `0x1415b9625`에서 2D 평면은 검사를 끄고, 나머지는 템플릿 검사값을 사용. 쓰기는 템플릿값을 유지해 `0x141615a70`에 전달 |
| 그리기 분기 | `0x1415b96eb`에서 종류 0은 `0x1415b5670`으로 호출 |
| 셰이더 선택 | `0x1415b56c4`의 선택 자원 `+0x438`이 없으면 `0x1415feff0`을 호출해 그룹 4 선택. 있으면 별도 그룹 5 경로 |
| 파일 등록 | `0x1416065b7`에서 그룹 4 슬롯에 CW_Quad.PS.cso 연결 |
| RGB 계수 전달 | `0x1415b9540`에서 템플릿 `+0xf0/+0xf4`를 블렌드 설명에 복사. `0x141615ad0` → `0x14161bed0`으로 상태 생성 |
| 쓰기 마스크 | 호출 전 `0x14060aaf0`이 8개 타깃 설명의 마스크를 0xF로 초기화. 조사한 재작성 분기는 이 마스크를 변경하지 않음 |

이는 조사한 정상 경로의 정적 연결이다. 모든 파티클에 같은 셰이더·상태가 선택되거나 실행 중 MRT2가 항상 연결된다는 뜻은 아니다. 메시·선택 자원·다른 호출 인자에 따른 분기도 같은 경로로 간주하지 않는다.

### RGB와 심도 입력의 블렌딩 분리

`0x14161beee~0x14161bf5e`의 분기는 다음 소스/대상 RGB 계수 쌍에서 IndependentBlendEnable을 켠다.

- SRCALPHA / DESTALPHA (5 / 7)
- SRCALPHA / ONE (5 / 2)
- ZERO / INVSRCCOLOR (1 / 4)
- ONE / ONE (2 / 2)

이때 타깃 1의 RGB 계수는 타깃 0에서 복사하고, 타깃 2의 RGB 계수는 **SRCALPHA / INVSRCALPHA (5 / 6)**로 바꾼다. 일반 SRCALPHA / INVSRCALPHA는 재작성 분기를 건너뛰고, 초기화된 IndependentBlendEnable=0에 따라 타깃 0의 설명이 적용된다. 따라서 가산 RGB 효과를 MRT2에서도 가산으로 계산하는 것은 이 경로와 맞지 않는다.

설명 생성자는 RGB·알파 연산을 ADD=1, 알파 계수를 ONE / ONE=2 / 2로 초기화한다. 이것은 뷰어의 투명 배경 커버리지용 ONE / INVSRCALPHA와 다르다. MRT2 알파를 뷰어의 커버리지 알파로 그대로 대체하지 않는다.

재작성 분기는 공유 float `0x142f9ac94`와 `0x142f9ab14`에도 1을 기록한다. **분기를 건너뛸 때는 이 구간에서 0을 기록하지 않는다.** 따라서 일반 블렌딩의 알파 모드를 항상 0으로 가정할 수 없다. 보고서의 `alpha_mode_write=null`은 0이라는 뜻이 아니라 이 호출에서 기록하지 않았다는 뜻이다.

추가 조사에서 두 주소가 PE의 zero-fill 가상 영역에 있어 런타임 초기화 전에는 0임을 확인했다. 파티클 종료 `0x1415b9791` → 상태 복원 `0x141615400` → 블렌드 복원 `0x141614e60`도 연결했다. 복원 함수는 저장된 상태를 찾으면 `0x141614ed6`에서 이전 GPU 블렌드 상태를 적용하고, `0x141614ef5~0x141614f00`에서 두 float를 0으로 쓴다. 저장된 항목을 찾지 못하면 `0x141614ec8`에서 이 전체 처리를 건너뛴다. 이전 float 값 자체를 저장했다 복원하는 동작은 아니다. 중첩 호출·다른 경로의 쓰기까지 확정한 결과는 아니다.

`blend_description()`은 이 생성자와 분기만을 재구성한 독립 계산 자료다. 기본 계수 11×11의 121개 입력에서 재작성 조건·타깃별 계수·쓰기 마스크·분기 생략 시 공유 상태 미확정을 검사한다. 실제 draw의 전체 상태를 읽어온 결과는 아니다.

### 공유 값의 상수 버퍼 업로드 (2026-11-03)

`audit_particle_depth.py`는 실제 QUAD·NOLIGHT DXBC의 SM5 RDEF 메타데이터에서 상수 버퍼 슬롯·변수 위치·크기를 읽는다. `audit_particle_render_state.py`는 실행 파일의 `0x141602648` 분기 테이블과 RIP 상대 주소에서 각 CPU 입력 버퍼의 주소를 계산해 같은 공유 값으로 이어지는지 확인한다.

| 셰이더 입력 | RDEF 슬롯/변수 | CPU 버퍼 주소 | Y 성분 주소 |
| --- | --- | --- | --- |
| QUAD `cb6[0].y` | CBPerQuad / g_v4UseTextureMaskMap, 슬롯 6, 오프셋 0, 16바이트 변수, 버퍼 128바이트 | `0x142f9ac90` | `0x142f9ac94` |
| NOLIGHT `cb5[19].y` | CBPerMaterial / g_v4MatUseTextureMaskMap, 슬롯 5, 오프셋 304, 16바이트 변수, 버퍼 480바이트 | `0x142f9a9e0` | `0x142f9ab14` |

CPU 입력 주소는 `0x1416024fa/0x14160250c`에서 선택하고 `0x14160252e`에서 등록한다. 일반 평면 파티클 그리기는 `0x1415b65a7~0x1415b65b1`에서 슬롯 6·크기 인자 0으로 `0x1415fb5f0`을 호출한다. 이 함수는 WRITE_DISCARD Map 후 등록된 CPU 입력과 등록 크기를 사용해 복사하고 Unmap한다. 슬롯 6 이상은 VS/PS 상수 버퍼 바인딩도 수행한다. 따라서 QUAD 알파 모드가 별도의 유사한 변수라는 추측이 아니라, 블렌드 분기가 쓰는 공유 float 자체가 업로드 입력에 포함된다.

이 연결은 조사한 일반 평면 경로의 QUAD 입력을 입증한다. NOLIGHT의 슬롯·필드 연결을 확인했다고 해서 모든 메시 파티클의 재질 업로드 시점까지 확인한 것은 아니다. 메타데이터 파서는 범위·버전·버퍼 중복/누락·변수 크기를 검사하며, 잘못된 테이블과 변수 위치를 넣은 회귀 검사도 포함한다.

### 장면 타깃과 개별 파티클 타깃의 구분

`0x140d7108a`는 장면 그리기 전에 `0x141609030`을 호출한다. 이 경로는 일반 RTV 배열 `+0xe0` 또는 MSAA RTV 배열 `+0x120`, 개수 `+0x21c`를 OMSetRenderTargets에 전달한다. DOF는 슬롯 2의 색상 SRV `+0x1b0`을 읽는다. 기존 [번짐 타깃 조사](AVATAR_BLOOM.md)의 생성·해제/resolve 및 슬롯 연결과 일치한다.

이는 장면 수준의 연결이다. 파티클의 가상 함수 호출·별도 그리기 경로가 타깃을 바꾸는지, 실제 타깃 개수가 얼마인지, 각 파티클이 그 장면 안에서 어느 시점에 그려지는지는 이번 정적 감사에서 확정하지 않았다. 보고서의 `targets.scope`에 이 경계를 명시하며, 개별 파티클의 실시간 MRT2 참여가 검증됐다고 표시하지 않는다.

## 실제 정의와 뷰어 정규화

아래 네 항목은 저장된 파생 인덱스에 의존하지 않고 원본 Lua 정의를 다시 읽어 대조했다. 두 Lua 파일의 해시도 감사 도구에서 확인한다.

| 정의 | 원본 깊이 검사/쓰기 | 뷰어 검사/쓰기 | RGB 블렌딩 |
| --- | --- | --- | --- |
| `FOOT_DUST` (`PARTICLE_SYSTEM_MAIN.LUA`) | 둘 다 생략 | 켜짐/꺼짐 | SRCALPHA / INVSRCALPHA |
| `PE_TRANSFORM_SYSTEM_CORE_GLOW_01` (동일 파일) | FALSE / TRUE | 꺼짐/켜짐 | SRCALPHA / DESTALPHA |
| `PE_CUSTOM_EF_FLOOR_WATER_WAVE` (`PARTICLE_SYSTEM_MAIN_EF1.LUA`) | 둘 다 생략 | 켜짐/꺼짐 | SRCALPHA / ONE |
| `PE_2026_SUMMER_DANCE_EMOTION_BG_NEON_SIGN` (동일 파일) | TRUE / TRUE | 켜짐/켜짐 | SRCALPHA / INVSRCALPHA |

생략된 값은 현재 뷰어의 기본 처리다. 이를 게임 엔진의 생성자 기본값까지 확인한 것으로 표시하지 않는다. 깊이 검사 꺼짐/쓰기 켜짐이라는 명시적인 조합도 그대로 보존한다.

## 뷰어 GPU 검증

`test_particle_depth_browser.py`는 `createParticleModel()`의 실제 InstancedMesh·입자별 알파 셰이더를 실행한다. 일반/가산 블렌딩 × 깊이 검사 켜기/끄기 × 깊이 쓰기 켜기/끄기 × 알파 0/0.5의 **16개 조건**에서 나중에 그리는 뒤쪽 표면이 가려지는지 대조한다.

- 깊이 검사·쓰기가 모두 켜지고 유효 알파가 있는 입자만 뒤쪽 표면을 가렸다. 검사 꺼짐/쓰기 켜짐은 이 WebGL 경로에서 깊이 가림을 만들지 않았다.
- 부분 알파도 깊이 쓰기가 켜지면 살아남은 픽셀의 깊이는 기록했다. 투명도를 곱한 깊이로 바꾸지 않는다.
- 텍스처의 완전히 투명한 부분은 뷰어의 알파 테스트로 제외되어 뒤쪽 표면을 가리지 않았다. 이 낮은 알파 컷오프는 기존 뷰어 처리이며 원본 QUAD의 색상 0 처리와 동일한 동작이라고 주장하지 않는다.
- 반투명·가산 입자를 불투명 보조 모델용 가림 목록에 전달해도 아바타 DOF 깊이에 임의로 포함하지 않는다. 깊이 준비 전후의 일반 파티클 출력도 픽셀 단위로 같아야 한다.

이 검사는 통제된 형상·텍스처와 현재 WebGL 렌더러의 동작을 검증한다. 원본 게임의 MRT2 블렌딩·깊이 상태나 인게임 화면과의 일치를 입증하지 않는다.

## 재검증과 다음 단계

### 명시적인 MRT2 GPU 비교 (2026-11-03)

`test_particle_mrt_browser.py`는 조사한 QUAD의 저알파 색상 0 처리·초점 기준 깊이 RGB·두 가지 알파 모드와 타깃별 블렌딩을 재구성한다. 실제 게임 셰이더를 실행하지 않는다. WebGL의 타깃별 블렌딩 지원에 의존하지 않도록 RGB 출력과 MRT2 출력을 동일 형상·순서의 **별도 UNORM8 패스**로 계산한다. 원본의 단일 MRT draw·MSAA·실시간 상태를 그대로 재생한 검사는 아니다.

일반·가산·DESTALPHA·ZERO/INVSRCCOLOR·ONE/ONE 블렌딩, 초기 알파 모드 0/1, 근거리/초점/원거리, 알파 0·1/255·0.5·1, 앞뒤 겹침과 깊이 검사/쓰기, 투명 구멍, 공유 상태 유지/복원을 포함한 **131개 조건**을 사용한다. Python 독립 계산이 매 draw의 UNORM8 저장·블렌딩·깊이 통과 여부를 계산하며, GPU의 양쪽 내부 픽셀과 형상 밖 픽셀을 **786개 비교**한다. 각 채널 오차 2 이내로 통과했다. 간단한 알파 모드 차이와 복원 결과는 수계산 예제로도 검증한다.

깊이 쓰기가 켜진 QUAD 경로에서는 저알파 표면 색을 0으로 만들어도 `discard`하지 않은 픽셀은 하드웨어 깊이를 기록해 뒤쪽 draw를 가릴 수 있다. 기존 뷰어 파티클의 낮은 알파 테스트는 그 픽셀을 버리므로 이 동작을 재현하지 않는다. 현재 뷰어는 투명 사각형이 다른 모델을 가리는 문제를 막기 위한 기존 동작을 유지한다. 이번 GPU 검사를 파티클 자체의 DOF가 구현되었다는 의미로 표시하지 않는다.

cd CLOSERS_Explorer
python -m unittest discover -s tests -p test_particle_depth_source.py -v
python -m unittest discover -s tests -p test_particle_depth_browser.py -v
python -m unittest discover -s tests -p test_particle_render_state.py -v
python -m unittest discover -s tests -p test_particle_mrt_reference.py -v
python -m unittest discover -s tests -p test_particle_mrt_browser.py -v
python tests/audit_particle_depth.py --workspace ../results --output ../diagnostics/particle-depth-source.json

- `PCT_3D_PLANE`, `ROL_EFFECT_0`~`ROL_EFFECT_58`, 깊이 검사 켜짐.

- DownUI·OverUI·InnerUI·UISeq가 켜져 있지 않음. 생략된 값은 기존 뷰어의 일반 장면 기본 해석이며 원본 생성자 기본값의 검증으로 표시하지 않는다.
- 메시·Spine·추적·바닥 연결·마스크·dissolve가 없음.

브라우저에서도 실제 InstancedMesh·재질·블렌딩을 다시 확인한다. 메시 원본이나 추가 마스크를 전달받은 생성 경로는 제외한다. 명시적인 `dof_plane` 필드가 없는 기존 인덱스는 자동 포함하지 않으므로 원본 인덱스를 갱신해야 한다. 현재 로컬 인덱스는 갱신했으며 정의 975개가 조건에 해당한다. 이는 화면에서 동시에 그리는 효과 수가 아니다.

`model-dof-depth.js`는 아바타 다음에 실제 파티클 인스턴스의 뷰 깊이를 같은 초점 수식으로 인코딩한다. 기존 입자별 알파·텍스처 구멍·깊이 검사·깊이 쓰기·그리기 순서를 사용한다. 일반 알파의 RGB 깊이 합성과 알파 ONE/ONE 누적을 적용하며, 프레임 종료 및 예외에서 임시 uniform·블렌드 상태·표시 상태를 복원한다. 요청되지 않은 효과와 숨긴 상위 그룹의 효과는 제외한다. 기존 불투명 보조 모델은 계속 깊이 가림만 제공한다.

`model-dof.js`는 부분 커버리지도 심도 합성에 사용하고 최종 화면 알파는 유지한다. 기존 메뉴의 **조명 · 재질 → 화면 효과 → 화면 효과 사용 → 초점 밖 흐림 사용**에서 보조 연출과 함께 확인한다. 현재 모델에 초점을 맞춘 뒤 초점 범위를 좁히면 앞뒤의 지원 파티클에도 흐림이 반영된다. 새 옵션이나 색상 진단은 추가하지 않았다. 시스루 아바타의 기존 심도 지원 제한은 유지한다.

검증은 실제 `createParticleModel`의 18개 깊이·알파·겹침 조합, 투명 텍스처 구멍, 숨김/요청 제외, 미지원 타입, 예외 복원, 전체 후처리의 RGB 변화·출력 알파 보존을 포함한다. 독립 CPU 계산은 매 draw의 UNORM8 양자화와 깊이 쓰기를 대조한다. 원본 `PE_RARE_7_BLAMB_BIKE_SKID_MARK` 정의와 실제 DDS 텍스처를 사용한 통제 GPU 검사도 통과했다. 화면상의 위치·크기·발생 시점은 검증을 위해 통제한 값이며 인게임 프레임 대조는 아니다.

원본과 동일하지 않은 범위도 남아 있다. 현재 뷰어의 저알파 discard를 유지하므로 원본 QUAD의 색상 0 처리 뒤 깊이 쓰기와 다를 수 있다. 이 단계는 일반 알파 모드만 구현하며 가산·DESTALPHA 등의 공유 알파 플래그, dual/masked/mesh 파티클의 MRT2 합성은 제외한다. 우선순위는 뷰어의 기존 레이어 정렬을 사용하며 게임의 조건부 상한 전환·자동 초점 상태를 재생하지 않는다. 다음 작업은 이 기본 경로의 실제 의상·모션 화면 비교와 미지원 합성 종류의 단계별 확대다.

### 실제 바이크 연출에서 확인한 가림 보완 (2026-11-03)

이세하 레어 7 의상 6부위, 공용 뼈, `MOTION_STRIKER_ATTACK.XMD`의 `ASTART`와 원본 바이크/타이어 자국 연출을 함께 표시하며, 효과용으로 로드한 본체 재질이 심도·번짐 가림에서 제외되는 문제를 찾았다. 효과 로더가 표면 전체에 투명·CustomBlending을 설정하기 때문에 실제로 불투명한 표면도 기존 불투명 보조 모델 검사에 들어오지 않았다.

효과 로더의 일반 패스를 명시적으로 표시하고, 현재 불투명도 1·일반 알파 블렌딩·깊이 검사/쓰기 켜짐·추가 알파 입력 없음·텍스처 알파가 전부 255인 표면만 가림에 포함한다. dissolve와 dual 보조 패스는 제외한다. 텍스처 알파 분류는 시스루와 같은 캐시를 사용하며 공통 모듈 `model-texture-alpha.js`로 분리했다. 실제 HTTP 모듈 제공 목록에도 등록했다.

바이크의 `bike_BLamb_01.png`는 알파가 모두 255이고, `bike_BLamb_02.png`는 183~255였다. 따라서 메시 전체를 불투명 처리하지 않고 재질 그룹별로 가림 대상을 고른다. 부분 알파·필터링된 cutout 경계·투명도 변화·가산 효과·알 수 없는 재질은 새 경로에 포함하지 않는다. 그룹의 표시 상태와 colorWrite는 성공·예외 모두에서 복원한다. 기본/MSAA의 혼합 재질 GPU 검사로 그룹별 가림과 원래 화면 복원을 확인했다.

### 실제 의상·모션·부모/자식 연출 통합 비교 (2026-11-03)

`test_particle_dof_motion_source_browser.py`는 다음 원본들을 읽어 재생한다. 캐릭터 동작은 XMD이며, 바이크 자체 동작은 해당 X 모델의 내장 애니메이션이다.

- 이세하 `RARE_7_A`의 머리·상의·하의·손·발·무기 6부위와 실제 텍스처.

- `XX_STRIKER_RARE_7_ASTART_BIKE.X`와 원본 자체 애니메이션.

기본 ASTART가 참조하는 여러 의상 연출 중 바이크 본체와 두 자식만 선택한다. 다른 의상 변형을 함께 재현했다고 표시하지 않는다. 의상·모션·부모 뼈·입자 수명·크기·위치·색상은 원본 패킷을 사용하며, 카메라와 수동 초점만 비교용으로 정한다. 테스트 API 응답은 원본 검증을 거친 모델/동작 데이터로 준비하고 실제 `setupMotionExtras`, `applyPose`, `createEmissionRenderer`를 실행한다.

생성 전 0.4초와 생성 후 0.9·1.2초, 정면/측면, 실제 발광 입력의 번짐 켜기/끄기를 조합한 **12개 조건**을 통과했다. 생성 전에는 파티클의 깊이/화면 기여가 없어야 하고, 생성 후에는 파티클을 심도에서 제외한 대조군과 깊이 및 RGB가 달라야 한다. 원래 출력 알파는 오차 1 이내로 유지하며 효과 해제 시 같은 프레임을 정확히 복원한다. 불투명 바이크 그룹의 가림과 부분 알파 그룹의 제외, 매 프레임의 재질 상태 복원도 확인했다.
