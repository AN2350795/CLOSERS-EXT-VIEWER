# 캐릭터 동작 탐색

전체 모델 분류, 전투 스킬·NPC·스킨 실제 명칭과 추출 통합 후처리는 [모델·모션 메타데이터](MODEL_METADATA.md)를 참고한다.

## 타운·던전 모션 전수 조사 (2026-11-06)

**동작 변경 → 아바타 타운 / 아바타 던전**은 파일명 분류에 더해 원본 변환 테이블의 클립 등록을 기준으로 찾는다. `COMMON` 파일에 들어 있는 타운용 대기·이동 모션도 포함한다. `RARE_7`, `CASH_MAID`, `타운 그룹 210`처럼 검색하고 **정보**에서 그룹 번호·상태·원본 테이블을 확인한다. 저장된 파일은 재생 검증 실패 여부와 관계없이 **원본 XMD 저장**으로 내려받을 수 있다.

라이브러리에서 **후처리만 실행**하면 선택적 `motion_catalog` 인덱스를 생성한다. 기존 연출 연결용 `motion_conversions`는 기본 상태를 확인할 수 없는 항목과 동일 클립 치환을 제외하므로 탐색의 전체 등록 목록으로 사용할 수 없다. 새 인덱스는 이를 별도로 보관하고 캐릭터 전용 행을 공통 행보다 우선한다. 같은 그룹·상태의 상충하는 등록도 삭제하지 않고 충돌로 표시한다. 등록은 실제 보유·착용 가능 여부를 보장하지 않으며, `RARE_*` 코드를 인게임 세트 이름으로 추정하지 않는다.

전체 XMD와 캐릭터 공용 뼈를 조사·추출하려면 프로젝트 루트에서 실행한다.

```powershell
python CLOSERS_Explorer/explorer.py motion-audit --destination results/motion-audit --extract
```

`--character STRIKER`를 추가하면 해당 캐릭터의 `MOTION_STRIKER*.XMD`와 공용 뼈 X로 범위를 좁힌다. `--extract`를 생략하면 조사 보고서만 만든다. 기본 전체 조사는 NPC·연출을 포함한 모든 XMD를 읽는다. 추출은 기존 Catalog의 원본 검증·충돌 보존·SHA-256 재개 경로를 사용하며, 추출 위치는 Catalog에도 기록한다. 저장 위치를 바꾸면 기존 파일을 보존하면서 새 위치로 추출한다.

`motion-audit.json`에는 출처별 클립·원본 해시·추출 경로·형식 해석 오류, 23개 캐릭터의 뼈 연결 결과, 등록돼 있지만 해당 캐릭터 파일에서 찾지 못한 클립을 구분해 저장한다. 공통 등록을 모든 캐릭터에 대조하므로 부재 항목은 실제 지원 누락의 확정 판정이 아니다. 형식 미지원·뼈 불일치도 복원 가능한 원본 XMD는 추출하며, 추출 성공이 뷰어 재생 성공을 뜻하지 않는다. 이전 이름 인덱스라면 등록 대조 불가를 보고하므로 후처리 후 다시 실행한다.

원본 XMD 버전 3의 12개 파일에서 모든 클립의 경계와 85,150개 뼈 변환을 검증하고 기존 버전 1·2와 같은 레이아웃 지원을 추가했다. 뼈 수·기본 자세·쿼터니언 검증과 입력 크기 제한은 유지한다. 헤더 없는 구형 XMD와 기본 자세가 맞지 않는 파일은 사유를 기록하고 재생을 보류한다.

기존 화면은 선택한 X 뼈 파일과 이름이 같은 XMD만 연결했다. 실제 캐릭터의 이동·공격·스킬·아바타 전용 동작은 `MOTION_<캐릭터>_*.XMD`에 나뉘어 있어 기본 목록만으로 확인할 수 없었다.

## 사용

**춤추기·춤추기 2**는 기본 춤만 재생한다. 조명을 추가하려면 **연출 설정 → 춤 조명 → 스포트라이트·음표**를 직접 선택한다. 기본값은 **없음 · 기본 춤**이며 동작을 바꾸면 해제된다. 이 메뉴는 해당 춤에서만 표시되고, 조명 선택으로 카메라 거리·방향을 바꾸지 않는다. 미러볼·눈사람·펫 연출은 기본 춤에 함께 적용하지 않는다. 개별 항목과 원본 정보는 **개별 연출·출처**에서 펼친다.

2026-11-05 세하의 춤추기·춤추기 2에 원본 캐릭터 상태의 `m_fAnimSpeed=0.5`를 반영했다. 개별 모션에서 이 값을 빠뜨려 원본보다 약 2배 빠르던 오류를 수정했다. 사용자 속도 1배는 원본 지정 속도를 따르며, 2배는 여기에 두 배를 곱한다. 묶음 모션은 기존 상태별 속도를 한 번만 적용한다. 타임라인은 XMD 키 시간을 표시하므로 세하의 춤에서 키 시간 1초는 기본 속도로 실제 2초에 해당한다.

음표와 스포트라이트는 원본 커스텀 장식 ID 13의 조명 하위 효과에 함께 정의돼 있다. 기본 춤에 항상 포함되는 연출이 아니다. 생성 평면의 UV가 원본 텍스처를 상하 반전하던 오류도 수정해, 광선이 원본 이미지처럼 위에서 아래로 퍼지도록 표시한다.

춤 장식 조건이 없는 이전 인덱스에서는 미확인 효과를 보류하고 후처리 갱신을 안내한다. 라이브러리의 후처리를 다시 실행하면 선택 장식 ID와 하위 효과 조건을 갱신한다. 이번 로컬 인덱스는 갱신했다. 확인 조합은 세하 휠 오브 트리니티 A와 **춤추기(`EMOTION_DANCE`) 약 1초**이며 의상에 관계없이 같은 춤 조명 메뉴를 사용할 수 있다.

3D 모델을 연 뒤 현재 동작 이름 옆의 **동작 변경**을 누른다. 종류 탭을 고르거나 파일명·동작명·보조 이름으로 검색하고 동작을 선택한다. 현재 이름이 갱신되면 아래 재생 영역의 **재생**·타임라인·반복·속도를 사용한다. 창 맨 위의 **기본 자세**는 뼈의 초기 자세로 복원하고 재생 조작을 비활성화한다. 이 선택 항목은 검색 결과와 별도로 항상 표시한다.

목록은 이름·시작/반복/마무리·길이 중심의 간결한 행으로 표시하며 현재 선택한 동작을 강조한다. 원본 코드·파일·경로·명칭 연결 근거·검증 오류는 각 행의 **정보**에서 펼친다. 검증용 `_DEFAULT` 클립과 설명은 **탐색 옵션 · 안내**에 두며, 모델의 기본 자세 선택과 구분한다. 파일을 바꾸면 기본 자세로 복원한 후 새 동작을 연결한다. 목록은 60개씩 표시하며 검색은 모든 파일의 모든 클립에 적용한다.

## 묶음 동작

**동작 변경 → 묶음 동작**은 개별 클립 목록과 별개로 데이터에서 연결이 확인된 묶음을 표시한다. 묶음을 선택하고 **재생**하면 시작 단계를 거쳐 반복 상태를 유지한다. 화면 아래 **종료하기**를 누르면 종료 동작을 재생한다. **종료 후**에서 **기본 자세** 또는 **마지막 자세 유지**를 선택한다. 마지막 자세를 유지한 경우 **재생**으로 묶음을 처음부터 다시 시작할 수 있다. 일시정지 중에도 종료를 요청할 수 있다.

묶음의 반복은 상태 연결에 따른 것이며 개별 클립의 **반복** 체크박스와 별개다. 묶음 재생 중에는 해당 체크박스를 비활성화한다. 속도 선택은 게임 상태별 `m_fAnimSpeed`에 곱해 적용한다. 타임라인은 현재 단계의 재생 위치를 보여주며, 시작 단계에서 종료를 요청하면 반복 상태의 취소 가능 시점까지 진행한 뒤 마무리한다. 반복 상태의 취소 가능 시간은 클립이 순환해도 누적한다.

후처리 시 스킬의 `m_UnitStateName`에서 시작해 상태의 `m_AnimEndChangeState`를 따라가고, `XAP_LOOP` 또는 `XAP_LOOP_NO_TRANSITION`의 반복 상태에서는 `m_CancelState`를 종료 경로로 읽는다. `m_vecUnitStateName_ETC`의 나열 순서나 파일명의 `_START/_LOOP/_END`만으로 순서를 추측하지 않는다. 상속된 상태 필드를 병합하며, 같은 계층의 연결이 충돌하거나 순환하거나 조건부 분기를 확정할 수 없는 경우 제외한다. 현재는 반복 상태 하나와 유한한 시작·종료 단계가 있는 경로를 지원하며, 임의의 스킬 콤보·공격 입력·변신 조건·게임 이벤트는 재현하지 않는다.

동작 목록 API는 `sequences`에 구성 클립과 출처·뼈·해시를 함께 반환한다. 모든 구성 클립이 한 파일에 있으면 각 출처를 별도 묶음으로 유지하고, 여러 파일에 나뉘면 단계별 출처와 공용 뼈를 하나로 확정할 수 있는 경우에만 연결한다. 없는 클립·중복 출처·뼈 불일치는 사유와 함께 표시한다. 선택 시 모든 단계의 키프레임을 검증해 미리 읽으며, 재생 전환 중에는 네트워크 요청을 하지 않는다. 묶음당 16단계·전체 300,000개 뼈 키 변환으로 제한한다.

묶음 정보는 기존 이름 인덱스의 선택적 `motion_sequences` 테이블에 저장한다. 이전 인덱스는 **후처리만 실행**으로 갱신하며, 인덱스가 없어도 개별 동작은 계속 사용할 수 있다. 모션 선택 변경·기본 자세·전체 초기화·모델 교체·화면 종료 시 묶음과 대기 중인 로딩을 해제한다.

현재 의상에 관계없이 같은 캐릭터의 아바타·이모션 모션을 포함한다. `RARE_3` 같은 코드로 묶음을 찾을 수 있다. 해당 모션의 착용·해금 조건은 추정해서 연결하지 않는다. 스킬은 실제 명칭이 연결되면 그 이름을 표시하고 원본 동작 코드를 함께 보존한다. 피격 대상·게임 로직은 포함하지 않는다. 선택적으로 연결된 보조 모델과 지원하는 메시 효과를 표시할 수 있다.

## 보조 모델과 메시 효과

모션 선택 후 **연출 설정**에서 **보조 모델 표시**와 **메시 효과 표시**를 각각 켠다. 기본값은 꺼짐이며 같은 브라우저에 선택을 저장한다. 목록의 체크박스로 개별 연출을 제외하고, 출처와 적용할 수 없는 사유를 확인할 수 있다. 묶음 동작을 선택하면 각 단계의 연출을 함께 준비한다. 연출은 장착 부위에 추가하지 않으며 모션 변경·기본 자세·초기화·모델 교체 시 별도로 해제한다.

후처리에서 캐릭터 상태 상속을 반영해 `m_vecAnimAddModelData`의 모션 → X 모델·뼈·오프셋과 `m_EventDamageEffect`의 생성 이벤트를 읽는다. `DAMAGE_EFFECT_DATA*.LUA`의 `m_MainEffectName`을 `X_MESH_PLAYER_GAME*.LUA`의 모델·동작·수명·색상 이벤트에 연결한다. 동일 이름의 정의가 다르면 자동 선택하지 않는다. 연결 결과는 기존 인덱스의 `motion_extras`에 저장하고 클립 API의 `extras`로 반환한다. 원본 경로와 모델 파일 ID는 현재 목록에서 다시 확인하며, 출처가 중복되거나 뼈가 없으면 표시를 보류한다. 인덱스 원본이 바뀌면 다른 이름 정보와 함께 무효화한다.

보조 모델은 뼈의 현재 행렬과 오프셋을 따라 표시한다. 메시 효과는 생성 시점·뼈 추적 여부·수명·선언된 자체 XMD·속도·반복·알파/가산 블렌딩·순차적인 색상 전환을 미리보기로 지원한다. 자체 XMD도 기존 기본 자세 검증을 통과해야 한다. 파티클 전용 효과, 빌보드, 중력, 이중 블렌딩, 지원하지 않는 이벤트, 회전 오프셋, 장비 조건은 임의로 재현하지 않으며 항목에 이유를 표시한다. 특수 게임 셰이더·사운드·물리·다중 입자 생성의 정확한 게임 화면 재현을 제공하는 기능은 아니다.

묶음 재생의 현재 단계에 해당하는 연출만 켜고, 상태 종료 시 해제하도록 지정된 효과는 다음 단계에서 숨긴다. 상태 종료 후 유지하도록 지정된 효과는 남은 수명 동안 유지한다. 타임라인을 되감으면 생성 이벤트도 다시 평가한다. 중간에 표시 옵션을 켜면 현재 재생 시점에 맞춰 미리보기를 시작하므로, 추적하지 않는 효과의 최초 생성 위치는 당시 프레임과 차이가 있을 수 있다. 일시정지는 연출 시간도 정지한다.

연출 모델은 동시에 16개·총 250,000 정점·300,000개 뼈 키 변환으로 제한하고 텍스처는 별도 참조 수 기반 캐시로 관리한다. 옵션 해제와 모션 교체 시 지오메트리·재질·텍스처 참조를 해제하며, 늦게 끝난 로딩은 현재 장면에 다시 추가하지 않는다. 전체 연출 인덱스는 직렬화한 스냅샷으로 유지하고 최근 32개 모션만 해석한 결과를 캐시한다.

## 이모션 인게임 명칭

추출 후처리의 이름 인덱스 생성은 이모션 명칭도 함께 저장한다. `SKILL_TEMPLET.LUA`의 이모션 스킬 ID와 상태 이름을 읽고, 캐릭터 Lua의 `BASE_TEMPLATE.m_GameUnitSubType` 상속을 따라 공통 상태 → 캐릭터 기본 상태 → 캐릭터 상태 순으로 `m_StateName`과 `m_AnimName`을 연결한다. `ST_<스킬 ID>_NAME` 키로 `STRING_TABLE_KOREA.NTF`, `STRING_TABLE_CHAR_KOREA.NTF`의 한국어 명칭을 찾는다. Lua를 실행하지 않고 정적 테이블만 읽는다.

이름이 확인되면 전체 탐색에서는 **인사하기**처럼 인게임 명칭을 먼저 표시하고 원본 클립명은 **정보**에 둔다. 재생 목록과 선택 완료 알림에는 명칭과 원본 코드를 함께 표시한다. 전체 탐색에서 한국어로 검색할 수 있다. 동일 클립을 여러 스킬이 공유하면 전체 탐색은 첫 명칭을 표시하고, **정보**에서 연결된 모든 명칭과 각 명칭의 스킬 ID·상태·상태 파일·문자열 테이블·문자열 키를 확인할 수 있다. 연결된 모든 명칭으로 검색할 수 있으며 효과·음악이 다른 스킬이 같은 뼈 동작을 사용할 수도 있다.

게임의 색상 태그는 표시에서 제거한다. 이름이나 상태 연결이 없거나 같은 계층의 상태 연결이 충돌하면 원본 클립명을 유지한다. 파일명 번역이나 다른 캐릭터의 유사 이름으로 명칭을 채우지 않는다. 원본에서 확인되는 반복·종료 상태만 해당 명칭에 연결한다.

이전 이름 인덱스도 계속 사용할 수 있으며, **후처리만 실행**으로 명칭을 추가할 수 있다. 갱신된 인덱스는 기존 이름·아이콘·장비 규칙과 함께 원자적으로 교체되고, 원본이 없어도 사용할 수 있다. 원본이 변경된 경우 오래된 명칭 연결을 무효화한다.

| 종류 | 파일명 근거 |
|---|---|
| 기본 · 이동 | `MOTION_<캐릭터>.XMD` |
| 전투 · 피격 | `ATTACK`, `CASH_ATTACK`, `DAMAGE` |
| 스킬 | `SKILL`, `TASKFORCE` |
| 아바타 변형 | `COMMON`, `RARE`, `DEVIL`, `CASH` |
| 이모션 | `EMOTION` 포함, 아바타 코드보다 우선 |
| 로비 · 마을 | `LOBBY`, `TOWN` |
| 상호작용 | `INTERACT` |
| 기타 | 나머지 관련 파일 |

## 데이터와 검증

`GET /api/model-motion-library?skeleton=<X 항목 ID>&entries=<장착 X 항목 ID 목록>`은 현재 목록에서 캐릭터 접두어가 정확히 일치하는 모든 XMD와 장착 모델·뼈의 동명 XMD를 찾는다. 숫자 접두어가 붙은 공통 액세서리의 동명 XMD도 포함한다. NPC·몬스터처럼 캐릭터 모션 접두어가 없는 모델은 동명 파일을 탐색한다. 파일명 일부가 비슷한 다른 캐릭터의 파일은 섞지 않는다.

파일별 출처·항목 ID·클립 인덱스·원본 이름·보조 이름·길이를 유지한다. 동일 이름의 XMD도 출처별로 별도 표시한다. 검색 목록에는 키프레임 전체를 보내지 않고 선택 시 기존 클립 API로 불러온다. 첫 탐색 때 관련 파일의 내용을 읽고 기본 자세를 검증하며, 모델을 바꾸면 화면의 탐색 결과를 초기화한다. 원본 추출 파일과 Catalog 분류는 변경하지 않는다.

현재 뼈와 XMD의 뼈 수 및 `_DEFAULT`의 시각 0 로컬 행렬을 대조한다. `_DEFAULT` 자체가 움직이는 파일은 첫 프레임으로 기준 자세를 검증하고 이후 키의 변환·회전 유효성을 검사한다. 발자국·충돌 보조 뼈는 스킨에서 사용하지 않고 실제 형상이나 일반 자식 뼈의 변형에도 관여하지 않는 하위 트리일 때만 자세 차이를 허용한다. 차이가 있는 보조 뼈와 첫 프레임 검증 여부는 동작의 **정보**에 표시한다. 몸체의 상대 오차 제한 0.005는 유지한다.

실패하면 동명 X 파일 후보, 캐릭터 기본 공용 뼈 순서로 별도로 검증하고 통과한 출처가 정확히 하나인 경우에만 뼈 전환을 제공한다. 특수 뼈를 사용하다 일반 모션을 선택하면 기본 공용 뼈로 돌아갈 수 있다. 후보가 없거나 중복되어 확정할 수 없으면 재생을 보류한다.

헤더 없는 구형 XMD도 지원한다. 뼈 수·클립 수 뒤에 각 키의 모든 뼈를 회전 4개·배율 3개·위치 3개 값으로 저장하는 형식이며 내부 버전은 `0`으로 보고한다. `_DEFAULT`가 없으면 정확히 동명인 X 파일과 클립 시작 시각 0의 모든 뼈 행렬이 일치할 때만 연결한다. 최신 형식의 검증 자세 누락에는 이 예외를 적용하지 않는다. 형식 해석 성공은 모든 클립의 재생 가능성을 보장하지 않는다.

2026-11-07 전수 검사에서 XMD 3,991개, 클립 29,697개를 해석했다. 캐릭터 23명의 1,691개 묶음에서 뼈 연결 실패는 203개에서 10개로 감소했다. 구형 311개 파일의 679개 클립 중 676개는 총 4,852,140개 뼈 변환을 검증했다. 나머지는 키 변환 150,000개 제한 초과 2개, 정규화되지 않은 회전 1개로 보류한다. 원본 파일은 그대로 추출할 수 있다.

구형 파일의 동명 모델 연결은 300개가 통과했다. 10개는 시작 자세가 일치하지 않고 1개는 동명 모델이 없어 연결을 보류한다. 클립 변환 검증과 모델 연결 검증은 서로 다른 검사이므로 두 검사를 모두 통과해야 선택한 클립을 재생할 수 있다. 남은 캐릭터 묶음 10개의 자세·뼈 구성 차이도 허용치를 늘려 우회하지 않는다.

읽기 오류·형식 미지원·뼈 불일치 파일도 오류 사유와 함께 목록에 남긴다. 클립 목록까지 읽은 경우 그 이름도 검색할 수 있다. `_DEFAULT`는 검증용이므로 처음에는 숨기며 체크박스로 포함할 수 있다. 파일별 기존 입력·키프레임 제한은 유지한다. 미추출 항목은 원본 CMF에서 읽고, 원본이 없어도 저장된 파일이 있으면 탐색할 수 있다.

## 확인

`test_model_motions.py`는 별도 묶음 발견, 다른 캐릭터 제외, 중복 출처, 오프라인 저장 파일, 손상 파일, 기본 자세 불일치, 전용 뼈 및 중복 전용 뼈를 검증한다. `test_motion_library_browser.py`는 한국어 명칭 표시·검색, 종류 필터·페이지 이동·검증 자세 표시·정확한 출처 선택·전용 뼈 전환·이전 모델 응답 무시를 Chromium에서 확인한다. `test_motion_names.py`는 후처리 생성, 상태 상속·덮어쓰기·공유 명칭, 출처 보존, 원본 변경 무효화, 세 모델 API의 명칭 전달을 확인한다.

`test_motion_sequences.py`는 연결 순서·상속·누락·분기·순환·출처 중복과 뼈 불일치를 검증한다. `test_motion_sequence_browser.py`는 상태별 속도·최소 취소 시간·반복 유지·일시정지 중 종료·종료 후 두 동작·재시작·개별 클립 전환·오래된 로딩 응답을 확인한다.

`test_motion_extras.py`는 연출 연결·상속 출처·타이밍·미지원 조건·중복 정의·리소스 선택을 검증한다. `test_motion_extras_browser.py`는 옵션에 따른 로딩·뼈 추적·효과 시점·색상 변화·되감기·단계 간 유지·자원 해제·오래된 응답 무시를 확인한다.

`test_motion_extras_lifecycle_browser.py`는 취소 신호를 무시하고 늦게 완료되는 모델·이미지 정보·텍스처 디코딩을 검사한다. 이전 응답이 새 선택의 로딩 상태를 해제하지 않고, 취소된 이미지 정보로 디코딩을 시작하지 않으며, 이미 진행 중인 디코딩 결과는 한 번만 해제해야 한다. 반복 종료 뒤 새 선택·오디오 활성화·버튼 활성화도 차단한다. 색상·장비 표시 복원, 앵커 제거, 후처리 적용 프레임의 픽셀 일치와 GPU 텍스처·형상 수 복귀를 함께 확인한다. 이미지 디코더는 완료 시점을 제어하는 1×1 테스트 텍스처로 대체하며 실제 파일 디코딩 속도를 측정하지 않는다.
