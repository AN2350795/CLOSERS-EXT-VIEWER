# 데이터 후처리 확장

웹의 추출 작업은 원본 파일 저장이 끝난 뒤 `closers/postprocess.py`의 `STEPS`를 순서대로 실행한다. 독립 실행 API는 `POST /api/postprocess`이며, 추출 API는 `postprocess: {enabled: true, executable: ".../CW.EXE"}` 설정으로 같은 실행기를 호출한다. 기존 API 호출에 설정이 없으면 자동 후처리하지 않는다.

현재 `game-data` 단계는 기존 `game_names.build_index`를 호출해 한국어 이름, 이모션 스킬·상태·클립과 명칭의 연결, 아이템 아이콘 연결과 PNG 본문, 장비 메시 우선순위와 프레임 그룹을 하나의 `game-names.sqlite3`에 저장한다. 아이콘과 이모션 이름의 원본은 추출 필터와 관계없이 분석된 CMF에서 읽으며, 같은 이름의 내용이 다른 출처는 자동 선택하지 않는다. 별도 진단 파일이나 개발 환경의 DB를 복사하지 않는다. 이전 인덱스에 새 테이블이 없어도 이름·모델 기능은 유지되며 후처리를 다시 실행하면 추가된다. [이모션 명칭 연결 방식](MODEL_MOTIONS.md#이모션-인게임-명칭)을 참고한다.

같은 단계에서 시작·반복·종료 상태 연결을 `motion_sequences`에 함께 저장한다. 목록 API는 이 정의를 현재 XMD 출처·뼈 검증 결과와 결합하므로 오래된 클립 ID를 고정 저장하지 않는다. [묶음 동작](MODEL_MOTIONS.md#묶음-동작)은 공통 상태와 캐릭터별 덮어쓰기를 반영하며, 명확히 이어지는 경로만 제공한다.

`motion_extras`에는 보조 모델 및 메시 효과 연결을 저장한다. 캐릭터가 참조한 효과만 DamageEffect·X Mesh Player 정의에서 골라 연결하며, 미지원 조건은 사유로 남긴다. 효과 정의 파일의 정적 테이블을 해석하지 못한 경우 기존 이름·모델 후처리는 계속하고 `extra_errors`에 기록한다. [보조 모델과 메시 효과](MODEL_MOTIONS.md#보조-모델과-메시-효과)는 클립 API에서 현재 리소스 출처를 확인한 뒤 선택적으로 표시한다.

새 단계는 `run(catalog, options, paths, cancel, progress)` 함수를 작성한 뒤 `Step('고유-ID', '화면에 표시할 이름', run)`을 `STEPS`에 추가한다. 웹은 등록된 단계 결과를 공통 형식으로 표시하므로 단계마다 새 작업 API를 만들 필요가 없다. 추가 입력이 필요하면 옵션 검증과 웹 입력도 함께 확장한다.

- 입력은 작업 폴더의 분석 목록과 사용자 원본에서 읽는다. 추출 필터에 제한된 파생 데이터를 전체 결과로 게시하지 않는다.
- 장시간 루프와 결과 게시 직전에 취소 이벤트를 확인하고 `Cancelled`를 발생시킨다. 진행 상태는 `progress(current='처리 대상')`로 전달한다.
- 단계는 자신의 출력 파일을 임시 파일에 만들고 검증 후 원자적으로 교체한다. 실패·취소 시 마지막 정상 출력과 추출 파일을 보존한다.
- 단계별 `result`는 JSON으로 표현할 수 있어야 한다. 일반 예외는 해당 단계의 오류로 기록하고 다음 독립 단계를 계속 실행한다. 의존 관계가 있는 처리는 같은 단계 안에서 실행한다.
- 기존 생성 함수를 재사용할 때 작업 폴더 잠금을 유지한다. 각 생성 함수가 잠금을 소유하므로 실행기에서 같은 잠금을 중첩하지 않는다.
- 반복 실행 가능하게 작성하고, 버전별 캐시를 도입한다면 코드 버전·설정·원본 변경을 함께 검증한다. 현재 이름 인덱스는 실행할 때마다 다시 생성한다.
- 새 산출물을 추가하면 데이터 관리의 전체 초기화 범위도 검토한다. 현재 이름 인덱스는 기존 초기화 대상에 포함되어 있다.

검증은 `tests/test_postprocess.py`의 실행 순서·실패 격리·독립 재실행·취소·API 인증 검사와 `tests/test_game_names.py`의 실제 NTF 합성 데이터 인덱스 생성 검사를 사용한다. 새 단계는 자기 결과의 정확성과 실패 시 기존 출력 보존을 추가로 검증한다.
