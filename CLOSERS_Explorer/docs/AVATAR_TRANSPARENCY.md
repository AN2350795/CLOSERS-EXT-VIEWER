# 아바타 시스루 표시

## 현재 동작

의상을 착용할 때 함께 연결되는 `ALPHA` 보조 모델은 실제 기본색 텍스처에 부분 알파가 있으면 반투명 합성한다. `_ALPHA` 파일명뿐 아니라 기본 텍스처·`_01` 텍스처를 공유하는 보조 모델도 적용한다. 별도 메뉴를 켤 필요가 없다. 의상 묶음이나 상의 착용으로 구성 모델을 함께 불러오면 적용된다. 원본 파일 보기에서 기본 모델만 단독으로 열면 보조 모델은 표시되지 않는다.

기존 코드는 X 재질의 `color.a < 1`인 경우에만 블렌딩을 켰다. 텍스처에 부분 투명도가 있어도 재질 알파가 1이면 구멍만 잘리고 나머지는 불투명하게 그려졌다. 이제 ALPHA 구성 모델은 재질 알파가 1이어도 실제 텍스처를 확인한다. 전체가 불투명한 텍스처와 0/255만 사용하는 구멍 텍스처는 깊이 쓰기를 유지한다. 기본 구성 모델·얼굴 SDF·일반 재질 알파의 규칙은 바꾸지 않는다.

부분 알파가 있는 옷감은 일반 알파 블렌딩·깊이 검사 켜짐·깊이 쓰기 꺼짐으로 그린다. 알파 테스트는 1/255로 낮춰 완전히 투명한 부분을 제외하면서 부드러운 옷감을 보존한다. 원본 알파에 임의 투명도 계수를 곱하지 않는다. 모든 이미지의 알파를 일괄 적용하지 않으며, 아바타 ALPHA 구성 모델이라는 출처가 필요하다.

`setAvatarBaseMap()`이 기본색 텍스처를 연결할 때 판정한다. 실제 뷰어·보조 모델·보존된 미리보기 렌더 경로가 같은 함수를 사용한다. 텍스처 캐시에 판정을 저장하고, 일반 이미지는 최대 64행씩 읽어 전체 해상도의 RGBA 복사본을 추가로 보관하지 않는다. 텍스처 출처를 바꾸면 새 이미지의 결과로 반투명/불투명 설정을 갱신한다. 조명·광택 등 보조 맵의 알파를 옷감 투명도로 취급하지 않는다.

## 하피 서머 아일랜드 확인 (2026-11-03)

`ROGUE / CLOTH_112_A·B·C` 상의의 기본·ALPHA 구성 모델과 실제 텍스처를 확인했다. A 타입 기본 모델 `300775604_…_UPBODY.X`와 보조 모델 `300775604_…_UPBODY_ALPHA.X`에는 두 ALPHA 텍스처 재질과 별도 기본 피부 텍스처 재질이 있다. 재질 불투명도는 모두 1이다.

A 타입의 256×256 기본 텍스처는 모든 픽셀의 알파가 255다. ALPHA 텍스처는 알파 0인 픽셀 6,385개, 1~254인 픽셀 52,624개, 알파 255인 픽셀 6,527개다. 따라서 부분 투명도가 누락되는 원인을 재질 알파만으로 판정하던 렌더러에서 재현할 수 있었다.

`test_avatar_alpha_browser.py`는 GPU 픽셀을 독립적인 알파 합성값과 대조한다. 반투명 한 겹 및 두 겹을 불투명 피부 위에 합성하고, ALPHA 구성 모델의 일반 피부 텍스처와 기본 구성 모델의 ALPHA 이름 텍스처는 변경되지 않는지 확인한다.

`test_harpy_summer_alpha_source_browser.py`는 로컬 원본에서 A·B·C 타입 상의를 찾아 기본/보조 모델 자동 구성을 확인한다. 실제 부분 알파·재질 알파 1·피부 재질 유지, 정면/측면의 시스루 출력과 강제 불투명 출력 차이, 블렌딩 복원 후 픽셀 일치를 검사한다. 실제 실행 중인 서버의 모델 뷰어에서도 A 타입의 두 보조 재질에 텍스처와 반투명 설정이 연결되는 것을 확인했다.

```powershell
cd CLOSERS_Explorer
python -m unittest discover -s tests -p test_avatar_alpha_browser.py -v
python -m unittest discover -s tests -p test_harpy_summer_alpha_source_browser.py -v
```

## 다른 시스루 의상과 기존 효과 병용 확인 (2026-11-03)

원본에서 다음 상의를 추가로 확인했다.

| 의상 | 구성 |

| 하피 비련의 서약 A (`ROGUE / CLOTH_224_A`) | ALPHA 보조 모델이 기본 상의 PNG를 공유 |
| 루나 아우라 픽시즈 A (`AEGIS / CLOTH_216_A`) | 다른 캐릭터의 원본 `_01.tga`를 공유하는 부분 알파·광택 재질과 완전히 불투명한 `_02.tga` 재질 |

파일명만으로 판정하던 기준은 이 세 경우를 놓쳤다. 이제 실제 알파로 판정하며 불투명 피부 이미지는 깊이 쓰기를 유지한다. 실행 중인 뷰어에서도 하피 비련의 서약의 공유 PNG 두 재질이 반투명으로 연결되는 것을 확인했다.

`test_avatar_alpha_variants_source_browser.py`는 세 의상을 정면·사선·양 측면·뒤의 다섯 방향에서 확인한다. 조명·광택·기본 번짐·5단계 번짐·색상 보정/선명도 병용의 **75개 조합**에서 알파 커버리지 유지와 임시 발광 플래그 복원을 검사한다. 실제 광택·마스크는 원본에 존재하는 경우에만 켠다. 번짐 패스를 실제로 실행하기 위해 별도의 통제된 발광 도형을 테스트 장면에 추가하며, 이 의상에 원본 발광이 있다고 표시하지 않는다.

각 시점에서 시스루/강제 불투명 출력의 차이와 복원 후 픽셀 일치를 확인한다. 심도는 지원 불가 판정과 요청 시 출력 유지도 검사한다. 다른 실제 의상 심도 검사도 공통 기본색 연결 함수를 사용하며 시스루가 확인된 경우 적용 보류, 지원 가능한 재질은 기존 초점/흐림 검사를 수행한다. 테스트의 정면·뒤·병용 캡처를 함께 검토했다. 복잡한 교차 삼각형의 픽셀별 정렬을 독립적으로 입증한 검사는 아니다.

### 겹친 옷감의 삼각형 정렬

비련의 서약을 뒤에서 보면 겹친 치마가 파일의 삼각형 순서대로 합성되어 네모난 조각처럼 보이는 문제를 확인했다. `model-alpha-sort.js`는 시스루 재질 그룹 내부의 삼각형을 현재 자세·모델 변환·카메라 기준의 평균 깊이로 정렬해 먼 면부터 합성한다. 기본 피부 등 불투명 재질 그룹은 정렬하지 않는다. 원래 정점·삼각형 구성과 재질별 그룹 범위는 유지하며 인덱스 버퍼를 재사용한다.

카메라/모델 행렬·스킨 뼈 행렬·시스루 그룹·그리기 범위가 같으면 정렬 결과를 재사용한다. 조명 조절이나 표면/발광 등 반복 패스마다 같은 정렬을 다시 하지 않는다. GPU 테스트는 한 메시 안의 두 겹 옷감을 독립 알파 합성값과 비교하고, 모델 뒤집기·뼈 자세 변경 및 복원·정지 상태의 재사용을 확인한다. 실제 치마 뒤쪽 캡처의 조각 얼룩도 수정 전후로 대조했다.

이는 그룹 내부의 삼각형 평균 깊이 정렬이다. 서로 교차하는 삼각형, 서로 다른 재질 그룹/메시가 얽힌 표면을 픽셀별로 정확히 정렬하는 방식은 아니다. 새 모듈의 실제 HTTP 제공 경로도 등록했고 뷰어 전체 import 그래프 검사와 실행 중인 서버의 페이지 로딩을 확인했다.

```powershell
python -m unittest discover -s tests -p test_avatar_alpha_variants_source_browser.py -v
```

## 남은 범위

원본 텍스처의 알파를 사용하는 기본 시스루 표시다. 게임의 모든 재질별 블렌딩·깊이 상태, 천의 두께/산란이나 인게임 프레임과의 일치를 확인한 것은 아니다. 시스루 그룹 내부는 평균 깊이로 정렬하며, 그룹 사이의 정렬은 Three.js의 일반 투명 렌더링을 따른다.

깊이 쓰기를 끈 시스루 재질은 현재 수동 심도 비교에서 지원하지 않는다. 해당 재질을 포함한 모델에서는 심도 비교를 보류하고 메뉴에 시스루 재질이 원인임을 표시한다. 메뉴를 추가하거나 저장된 심도 설정을 지우지 않는다. 인게임 화면 대조와 복잡한 교차 삼각형 정렬, 시스루에 대한 별도 심도 합성은 추가 범위다.

기본 시스루 자동 적용·대표 의상의 방향별 표시·기존 효과 병용·심도 지원 범위 정리를 이번 단계의 완료 범위로 삼는다. 다음은 기존 파티클 심도 작업을 재개한다.
