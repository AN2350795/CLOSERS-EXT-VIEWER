# 아바타 시스루 표시

## 현재 동작

의상을 착용할 때 함께 연결되는 `ALPHA` 보조 모델 중, `_ALPHA` 텍스처를 쓰는 재질은 텍스처 알파로 반투명 합성한다. 별도 메뉴를 켤 필요가 없다. 의상 묶음이나 상의 착용으로 구성 모델을 함께 불러오면 적용된다. 원본 파일 보기에서 기본 모델만 단독으로 열면 보조 모델은 표시되지 않는다.

기존 코드는 X 재질의 `color.a < 1`인 경우에만 블렌딩을 켰다. 텍스처에 부분 투명도가 있어도 재질 알파가 1이면 구멍만 잘리고 나머지는 불투명하게 그려졌다. 이제 아바타 ALPHA 구성 모델과 ALPHA 텍스처의 조합은 재질 알파가 1이어도 블렌딩을 켠다. 피부·기본 재질·얼굴 SDF·일반 재질 알파는 기존 규칙을 유지한다.

반투명 옷감은 일반 알파 블렌딩·깊이 검사 켜짐·깊이 쓰기 꺼짐으로 그린다. 알파 테스트는 1/255로 낮춰 완전히 투명한 부분을 제외하면서 부드러운 옷감을 보존한다. 원본 알파에 임의 투명도 계수를 곱하지 않는다. 모든 `_ALPHA` 이름의 이미지를 일괄 반투명 처리하지 않으며, 아바타 ALPHA 구성 모델이라는 출처가 필요하다.

## 하피 서머 아일랜드 확인 (2026-11-03)

`ROGUE / CLOTH_112_A·B·C` 상의의 기본·ALPHA 구성 모델과 실제 텍스처를 확인했다. A 타입 기본 모델 `300775604_…_UPBODY.X`와 보조 모델 `300775604_…_UPBODY_ALPHA.X`에는 두 ALPHA 텍스처 재질과 별도 기본 피부 텍스처 재질이 있다. 재질 불투명도는 모두 1이다.

A 타입의 256×256 기본 텍스처는 모든 픽셀의 알파가 255다. ALPHA 텍스처는 알파 0인 픽셀 6,385개, 1~254인 픽셀 52,624개, 알파 255인 픽셀 6,527개다. 따라서 부분 투명도가 누락되는 원인을 재질 알파만으로 판정하던 렌더러에서 재현할 수 있었다.

`test_avatar_alpha_browser.py`는 GPU 픽셀을 독립적인 알파 합성값과 대조한다. 반투명 한 겹 및 두 겹을 불투명 피부 위에 합성하고, ALPHA 구성 모델의 일반 피부 텍스처와 기본 구성 모델의 ALPHA 이름 텍스처는 변경되지 않는지 확인한다.

`test_harpy_summer_alpha_source_browser.py`는 로컬 원본에서 A·B·C 타입 상의를 찾아 기본/보조 모델 자동 구성을 확인한다. 실제 부분 알파·재질 알파 1·피부 재질 유지, 정면/측면의 시스루 출력과 강제 불투명 출력 차이, 블렌딩 복원 후 픽셀 일치를 검사한다. 실제 실행 중인 서버의 모델 뷰어에서도 A 타입의 두 보조 재질에 텍스처와 반투명 설정이 연결되는 것을 확인했다.

```powershell
cd CLOSERS_Explorer
python -m unittest discover -s tests -p test_avatar_alpha_browser.py -v
python -m unittest discover -s tests -p test_harpy_summer_alpha_source_browser.py -v
```

## 남은 범위

원본 텍스처의 알파를 사용하는 기본 시스루 표시다. 게임의 모든 재질별 블렌딩·깊이 상태, 천의 두께/산란이나 인게임 프레임과의 일치를 확인한 것은 아니다. 겹친 삼각형의 정렬도 Three.js의 일반 투명 렌더링 한계를 따른다.

깊이 쓰기를 끈 시스루 재질은 현재 수동 심도 비교에서 지원하지 않는다. 해당 재질을 포함한 모델에서는 기존 지원 판정에 따라 심도 비교를 보류하고 메뉴에 사유를 표시한다. 번짐·색상 보정·선명도와의 병용, 다른 ALPHA 의상의 정렬 및 게임 화면 대조는 추가 확인 범위다.
