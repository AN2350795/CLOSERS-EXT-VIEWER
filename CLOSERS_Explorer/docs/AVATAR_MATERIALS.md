# 아바타 재질 조사와 표시 범위

2026-10-24 로컬 게임 원본을 읽어 검증했다. 원본 CMF, CW.EXE, 기존 추출 에셋은 수정하지 않는다.

## 적용 범위

### 조명 착용 조건 진단과 조건별 선택 연결 (2026-10-31)

`NEW_CONVERT_TEMPLET.NTF`의 실제 조명 연결 열과 `CONVERT_ITEM_GROUP_LIST1/2/3.NTF`의 아이템 번호를 연결했다. 모델 장면에 조건별 개수·미충족·확인 보류 상태를 포함하고 조명 창에 표시한다. 조건을 충족한 후보가 하나일 때 버튼으로 선택할 수 있으며, 조명 효과는 자동으로 켜지지 않는다. 복합 메시 중복 계산과 같은 부위 중복 착용을 방지한다.

황천의 사자는 10개 조건이지만 실제 미래 원본 장면의 표시 가능한 8개 아이템만으로는 미충족이다. 일반 스킨 1343·1411은 조명 목록에 있어도 이 경로의 조명 연결이 0이다. 따라서 의상 이름으로 조명을 강제 자동 적용하지 않는다. 다음은 별도 착용 경로·비표시 아이템과 게임의 스킨 선택 상태·우선순위 연결이다. 주소·검증·한계는 [조명 착용 조건 진단](AVATAR_LIGHT_CONDITIONS.md)에 기록했다.

### 얼굴 음영의 머리 기준 프레임 연결 확정 (2026-10-31)

원본의 뼈 이름 표에서 `BIP01_HEAD`는 7번이다. 로더는 이름 조회 결과를 프레임에 기록하고 39개 뼈 슬롯 배열의 해당 위치에 연결한다. SDF 업로드는 이 배열의 `+0x38`, 즉 7번 슬롯을 선택하여 세계 행렬을 읽는다. 현재 머리 뼈 선택은 원본과 일치하므로 렌더링 대상을 변경하지 않고, 바인딩 메타데이터를 확인된 상태로 정정했다. 전체 미리보기의 근사 표시는 툰 강도·후처리 등 남은 차이 때문에 유지한다.

`tests/audit_face_binding.py`로 원본 SHA256과 근거 7곳을 재검사한다. 누락·동명 뼈·눈 제외 규칙과 실제 4개 캐릭터의 메타데이터·축·동작도 검증한다. 근거는 [법선·얼굴 기준 검증](AVATAR_NORMAL_BASIS.md)에 정리했다. 다음 우선 작업은 의상·세트 조건과 원본 조명 선택을 연결하는 것이다. 자동 거리·회전, EXT B 계수, 장면별 후처리와 동일 조건 인게임 대조는 남아 있다.

### 원본 접선 생성 방식 적용 (2026-10-31)

원본 BUMP 연결 시 호출하는 접선 생성 함수 `0x141745f80`을 찾았다. 원본은 삼각형별 UV 미분을 정점에 누적해 접선·종법선을 각각 평균·정규화하고, `cross(N,T)`와의 내적 부호로 종법선을 뒤집는다. 추가 직교화나 종법선 외적 재구성은 하지 않는다. 기존 Three `computeTangents` 경로를 이 방식으로 교체했다. 원본 위치·법선·UV·면·가중치는 유지한다.

새 기준 검사는 수정 전 실패·수정 후 통과했다. 대칭 UV·비스듬한 UV·공유 정점 평균·스킨 변형·퇴화 입력과 기존 반사·광택·색상 보정을 검증하며 실제 의상도 대조한다. 유효하지 않은 삼각형은 제외하고 기존 fallback을 유지한다. 자세한 주소·식·한계는 [법선·얼굴 기준 검증](AVATAR_NORMAL_BASIS.md)에 기록했다. 얼굴의 원본 뼈 슬롯 연결도 추적했으며 다음 검증 단위에서 바인딩 근거와 메타데이터를 정리한다.

### 얼굴 SDF alpha의 원본 mip 0 조회 수정 (2026-10-31)

얼굴 alpha의 좌우 반전 조회와 일반 조회를 모두 원본 PS처럼 mip 0으로 고정했다. 자동 mip을 쓰던 기존 경로는 화면 축소 시 얼굴 음영 데이터가 바뀔 수 있었다. 기본색 RGB·눈·불투명도는 바꾸지 않는다. 낮은 mip에 상반된 alpha를 넣은 GPU 검사는 수정 전 실패·수정 후 통과했고, 부모 뼈의 회전·이동과 머리 크기 변형에서도 정면 축의 부호·명암을 대조했다.

실제 4개 캐릭터 얼굴과 이슬비 공통 동작에서 좌우 음영·눈 제외·알파·포즈 복원을 확인했다. 하이퍼 모드 효과는 꺼진 조건이다. 근거는 [표면 법선·얼굴 기준 검증](AVATAR_NORMAL_BASIS.md)에 추가했다. 다음은 원본의 얼굴 기준 프레임 포인터와 현재 머리 뼈 바인딩의 대응, 접선 생성 규칙을 확인하는 작업이다. 조명 자동 적용·거리·회전, EXT B 계수, 다른 후처리와 인게임 대조도 남아 있다.

### 원본 정점 법선 변환·정규화 수정 (2026-10-31)

표면 굴곡 경로에서 원본과 다른 법선 변환·보간을 수정했다. 원본 VS는 직접 세계/뼈 행렬 변환 후 정점마다 정규화하지만, 뷰어는 역전치 법선을 정규화하지 않고 보간했다. 굴곡용 뷰 법선과 툰·EXT·테두리광의 세계 법선을 원본 방식으로 맞췄다. 새 GPU 회귀 검사는 수정 전 실패·수정 후 통과했으며 기본/4/5 가중치·크기 변형·좌우 반전을 대조한다. 하이퍼 모드 효과는 검증 조건에 포함하지 않는다.

얼굴의 좌우 1번 열·정면 2번 열 선택은 원본 셰이더와 일치했다. 실제 원본 프레임 포인터와 `BIP01_HEAD`의 대응은 계속 미확정이므로 축을 임의로 바꾸지 않았다. 근거와 한계는 [표면 법선·얼굴 기준 검증](AVATAR_NORMAL_BASIS.md)에 기록했다. 다음은 원본의 얼굴 alpha mip 0 샘플링과 현재 자동 mip 샘플링 차이를 수정·검증하는 작업이다.

### 원본 그래픽 프리셋의 색상 수치 적용 (2026-10-30)

`GRAPHIC_OPTION_DATA_DETAIL.NTF`의 범위 정의와 프리셋 적용 함수 `0x140092700`을 대조했다. 범주 5의 숫자 열 7~12는 RGB·밝기·대비·채도이며, 원본 범위 검사를 통과한 여섯 값 중 양수가 있으면 색상 보정을 활성화한다. 로컬 원본의 프리셋 7개는 모두 활성이다. 프리셋 4의 채도 0은 비활성이 아니라 실제 무채색 보정이다. 원본 소수의 float32 값은 그대로 보존한다.

조명 API에 색상 프리셋 목록과 출처 SHA256·행 번호·원본 활성 여부를 추가했다. 캐시 버전은 6이다. 프리셋 손상은 조명 목록과 분리하여 처리하고, 원본이 없으면 추정 프리셋을 만들지 않는다. 색상 정의의 누락·중복·범위 변경·NaN/무한대·범위 초과 프리셋은 거부한다.

색상 보정 비교에서 프리셋을 선택하고 적용 버튼을 눌렀을 때만 수치를 복사한다. 보정 켜짐과 다른 효과는 유지한다. 첫 적용 전 직접 입력값을 별도로 저장하므로 프리셋을 여러 번 바꿔도 복원할 수 있다. 직접 입력 수정과 중립 초기화는 이전 복원값을 지운다. 원본 표 읽기·오류 격리·수동값 저장 복원·채도 0·여러 프리셋 전환·보정 OFF 유지·기존 색상 비교를 검증한다. 출력 감사 도구의 근거는 24곳으로 확장했다. 프리셋 표 감사 결과는 `diagnostics/color-grading-presets-20261030.json`에 보관한다.

다음은 원본 접선·얼굴 기준 축을 대조하여 표면 굴곡과 얼굴 음영의 방향 오차를 줄이는 작업이다. 장면별 프리셋 덮어쓰기·다른 후처리, 조명 자동 선택·거리·회전, EXT B 계수, 인게임 화면 대조도 남아 있다.

### 원본 식의 색상 보정 비교 렌더링 (2026-10-30)

**조명 · 재질 → 원본 형식의 색상 계산 비교 → 색상 보정 비교**에 RGB 배율·밝기·대비·채도의 수동 비교를 추가했다. 기본은 OFF·중립값이며 저장한 명시적 선택만 복원한다. `model-color-grading.js`는 검증한 밝기→대비→RGB 배율→채도 식을 사용하고, `model-emission.js`는 발광·번짐 합성이 끝난 뒤 최종 출력 변환 전에 한 번 적용한다. 발광이 없는 모델에도 별도 화면 패스로 적용한다. 조명·광택 자체의 수치는 바꾸지 않는다.

원본 형식 비교가 꺼지거나 모델이 없으면 보류한다. 발광만 보기·광택 마스크 확인도 보류하여 진단 화면의 수치를 유지한다. 설정은 보존하므로 조건을 복원하면 다시 적용된다. 중립값 버튼은 켜짐 선택을 유지하고 수치만 초기화한다. 숫자가 비어 있거나 잘못되면 마지막 유효 입력을 유지하며 저장 벡터가 유효하지 않으면 중립값으로 복구한다. UI 범위는 RGB 0~2, 밝기 -1~1, 대비 -1~2, 채도 0~2의 비교 범위이며 게임 수치의 범위라고 주장하지 않는다.

GPU 검사는 일반/4/5 가중치, 비중립 식·상하한 clamp·중립값, 발광/번짐 이후 적용, 반투명 alpha, 최종 색 변환 한 번 적용, OFF 정확 복원, 크기 변경과 렌더 상태 복구를 대조한다. DOM은 초기 OFF·저장된 ON·수치 저장·잘못된 입력·중립값·원본 비교 OFF·진단 보류·모델 재로딩/지우기를 확인한다. 실제 오로라 픽시즈 B의 앞/옆/뒤에서도 아바타 픽셀 변화와 OFF 복원을 검사한다. 캡처는 `diagnostics/color-grading-20261030/`에 보관한다. 서버의 새 모듈 제공 경로도 검증한다.

다음은 게임 프리셋이 색상 보정 활성값과 수치를 정하는 경로를 확인하는 작업이다. 현재 수동 비교값은 인게임 자동 재현 설정이 아니다. 접선·얼굴 기준 축, 조명 자동 선택·거리·회전, EXT B 계수, 동일 조건의 인게임 비교도 남아 있다.

### 색상 보정 활성값·셰이더·상수 연결 확인 (2026-10-30)

설정의 `ColorGrading`이 후처리 bit 5를 지정하고, 해당 마지막 패스가 기법 16으로 `CW_ColorGrading.PS.cso`를 선택하는 연결을 확인했다. RGB·BCS 입력에서 대비·채도·밝기·RGB 배율을 만드는 CPU 상수 작성 경로도 대조했다. 빈 데이터의 기본값은 중립이며 노출은 이 경로에서 0이다. 밝기→대비→RGB 배율→채도의 순서로 계산하고 마지막에 clamp한다. 이 PS 자체에는 추가 감마 변환이나 필름형 톤 매핑이 없다.

조사 PC의 저장 설정에는 중립이 아닌 RGB·BCS가 있지만, 프리셋과 시스템 설정이 활성값을 별도로 지정하므로 공통 기본값으로 자동 적용하지 않는다. [출력 색상 경로 조사](AVATAR_OUTPUT_COLOR.md)에 전체 연결과 식을 기록했고 감사 도구의 대조 근거를 20곳으로 확장했다. 이번 단계는 조사·감사 도구 변경이며 렌더링 기본값은 유지한다. 다음 구현은 확인한 색상 보정식의 비교 렌더링과 GPU 검증이다.

### 출력 RTV 설정 연결 확인 (2026-10-30)

기본 장치 설정과 성공한 설정 검증 경로는 Format 28을 지정한다. 앱이 등록한 설정 콜백은 Format을 바꾸지 않으며, 현재 설정의 `+0x28`이 초기 생성·크기 변경에 쓰이는 RTV descriptor로 전달된다. 해당 RTV 생성 함수는 감마 플래그나 28→29 변환 함수를 사용하지 않는다. 확인한 일반 생성 경로에는 추가 하드웨어 sRGB 쓰기 변환을 지정하지 않는다. 다만 장면의 최종 출력 경로 전체와 후처리 활성값은 아직 미확정이다.

주소별 근거와 후처리 패스의 조건부 호출 순서는 [출력 색상 경로 조사](AVATAR_OUTPUT_COLOR.md)에 기록했다. `tests/audit_output_color.py`로 조사한 실행 파일의 SHA256과 근거 바이트 10곳을 재검사할 수 있다. 다른 실행 파일은 실패 처리하며 게임 실행·원본 변경은 하지 않는다. 색상 비교 모드의 기본 OFF는 유지한다. 다음 작업은 후처리 활성 비트의 설정 주체와 기법 `0x10`의 셰이더·상수 연결 확인이다.

### 출력 형식 추적과 입력·출력 색상 계산 비교 (2026-10-30)

`0x1417bc979`은 스왑체인 descriptor Format에 `0x1c`를 쓰고 `0x1417bc99b`에서 IDXGIFactory의 CreateSwapChain(+0x50)을 호출한다. 반면 `0x1417bc330~0x1417bc33f`의 출력 RTV 생성(+0x48)은 별도의 현재 설정값에서 Format을 가져온다. 엔진에는 상태+0x497을 읽는 `0x1417b8300`과, 이 값에 따라 UNORM 28을 sRGB 29로 바꾸는 `0x1417c6790`도 있다. 그러므로 스왑체인 형식만으로 최종 출력 감마를 단정하지 않는다. 실제 게임 장면의 출력 뷰 선택과 후처리 활성 순서는 미확정이며, 정적 근거는 `diagnostics/output-color-source-20261030.txt`에 보관한다.

**조명 · 재질 → 원본 형식의 색상 계산 비교 (후처리 미포함)**는 입력·출력 도메인을 함께 전환하는 비교 모드다. 초기에는 OFF로 기존 화면을 유지하고 사용자가 켠 선택만 저장한다. ### XET 반사의 원본 지역 광원 위치 비교 (2026-10-30)

**조명 · 재질 → 광택 켜기 → 원본 표면 굴곡·광택 마스크 사용 → 원본 반사색·반사 지수 사용 → 반사 광원: 선택 지역 · 원본 광원 위치**로 켠다. 의상 조명 목록에서 평화의 광장/몽마르트르 황혼을 선택하면 된다. 기본값은 기존 카메라 확인용 광원이며 선택은 저장한다. 원본 툰이 꺼져 있어도 반사 광원 비교가 가능하다. 반사 수치가 없는 아이템에는 반사를 추가하지 않는다.

### 광택 마스크 범위 확인 모드 (2026-10-30)

**조명 · 재질 → 광택 범위 확인**은 원본 BUMP를 mip 0으로 읽고, RGB 중 0보다 큰 성분이 있으면 알파를 회색조로 표시한다. RGB가 모두 0이면 검정이다. 실제 MatCap 분기와 같은 유효성·마스크를 확인하는 진단 화면으로, 새로운 인게임 효과가 아니다. 흰색은 광택 허용, 검정은 제외, 회색은 부분 허용이며 마스크만으로 최종 광택 밝기를 확정하지 않는다.

광택 master·툰·조명 선택과 독립적으로 켤 수 있다. 원본 마스크가 있는 연결만 표시하고 재질별 제외는 유지한다. 마스크를 기본색·발광 뒤의 최종 표면에 표시하여 색과 음영이 범위를 가리지 않게 하며 원래 투명도는 유지한다. 확인 중에는 뷰어의 발광만 보기·번짐 합성을 잠시 보류하지만 설정은 바꾸지 않는다. 실제 발광 패스에는 마스크를 넣지 않는다. OFF 시 기존 재질 화면과 발광/번짐 선택이 복원되고, 마스크가 없거나 모델을 지우면 확인 모드도 꺼진다. 확인 모드는 저장하지 않는다.

XET 재질 규칙 조사에서 MatCap+반사 205개, MatCap만 747개를 확인했고 반사 수치만 있는 행은 없었다. 이 수는 조사한 로컬 원본 규칙의 행 수이며 모든 캐릭터·타입의 시각 검증 완료를 뜻하지 않는다. 연결되어도 해당 UV의 마스크가 0이면 광택이 안 보일 수 있으므로, 이 확인 화면으로 원인을 구분한다.

GPU 검사: 일반/4/5 가중치에서 알파 회색조 수치·RGB 무효 시 검정·원래 알파/무관한 재질 유지·발광 오염 방지·실제 발광 패스 분리·OFF 정확 복원을 검증한다. DOM 검사: 광택 OFF 상태의 독립 활성화·누락 마스크 보류·설명·OFF를 포함한다. 실제 유광 코스튬의 마스크와 복원 화면은 `diagnostics/gloss-mask-20261030/`에 보관한다.

원본 접선/얼굴 기준 축과 색공간·후처리 차이, 세트·옷장 조건의 조명 자동 선택, 자동 거리·회전, EXT B 계수 연결도 남아 있다. 하이퍼 모드 자동 발동·애니메이션은 일반 조명·유광 개선 뒤로 둔다. 최종 외형 일치는 같은 코스튬·포즈·카메라·조명의 인게임 기준 화면과 별도로 비교해야 한다.

### 조명 선택 시 숨겨진 구형 색상 비교 자동 활성화 수정 (2026-10-30)

조명 선택기는 원본 툰 항목 안에 있지만, 툰이 OFF인 채 조명을 선택하면 이전 구현은 접힌 **기존 색상 수치 비교**를 자동으로 ON으로 바꿨다. 사용자가 툰 조명을 선택했다고 생각해도 실제로는 기본색에 구형 방향별 색 혼합이 적용되는 문제였다. 선택기는 이제 선택만 저장하고, 직접 켜진 모드의 참조만 갱신한다. 툰·구형 비교가 모두 꺼져 있으면 기본 표면을 유지하고, 원본 툰을 켜라는 안내를 표시한다. 조명 선택을 해제하면 구형 비교도 OFF가 되며 다시 선택해도 자동으로 켜지지 않는다.

과거 자동 활성화 설정과 사용자의 수동 선택을 구분할 수 없어, `legacyExplicit` 표시가 없는 이전 구형 비교 ON 설정은 OFF로 이관한다. 이후 접힌 구형 비교 항목의 체크박스를 직접 켠 경우에만 그 선택을 저장·복원한다. 원본 툰·광택·발광 설정은 유지하며 두 조명 모드를 동시에 적용하지 않는다.

황천의 사자 원본 값은 RGB `(0.3,0.3,0.3)`, 원거리·근거리 강도 모두 약 `1.025`다. 원본 툰에서도 어두운 조명이므로 이를 임의로 밝게 바꾸지 않았다. 이번 수정은 숨겨진 구형 비교가 예상 밖으로 적용되는 원인을 제거한 것이며, 찰흙처럼 보이는 모든 원인이나 최종 인게임 외형을 해결했다고 판단하지 않는다. 실제 오로라 픽시즈 B 타입으로 툰/광택 합성 및 황천 조명 적용·OFF 복원을 대조하고, 캡처를 `diagnostics/netherworld-mode-20261030/`에 보관한다.

회귀 검사는 수정 전 조명 선택만으로 구형 비교가 켜지는 상태에서 실패했다. 수정 후 조명 선택·선택 해제/재선택·과거 저장값 이관·명시적 구형 비교·모델 재로딩·소스 실패/복구·툰 배타 적용을 검사한다. 원거리/근거리·얼굴 SDF·GLOW·EXT·rim·SecondMap 검사도 유지한다.

### 광택 마스크 누락·지연 시 전체 표면 광택 수정 (2026-10-30)

원본 마스크 사용이 켜져 있어도 BUMP가 아직 로드되지 않았거나 누락되면 기존 뷰어는 `capMask=1`로 MatCap을 표면 전체에 더했다. 로딩 순서에 따라 잠시 전체가 번들거리거나, 마스크가 없는 부위가 계속 매끈해지는 동작이다. 최신 PS는 BUMP RGB의 유효 분기 안에서만 MatCap을 샘플링하므로 기본 모드의 무마스크 대체 적용을 제거했다. 이제 MatCap과 BUMP가 모두 준비되어야 적용하며, BUMP 연결이 사라지면 즉시 기본 표면으로 복귀하고 복구하면 저장된 설정으로 다시 적용한다.

마스크가 없으면 적용 보류·확인 필요를 표시하고 현재 표시 수에서 제외한다. **원본 표면 굴곡·광택 마스크 사용**을 직접 끈 경우에만 기존 정점 법선·전체 표면 비교를 허용하며 그 의미를 명시한다. 반사는 계속 원본 BUMP 마스크를 필요로 한다. 이 변경은 무마스크 광택의 원인 한 가지를 수정한 것이며, 황천의 사자 조명을 포함한 전체 인게임 외형 일치를 확인한 것은 아니다.

GPU 회귀 검사는 수정 전 ‘BUMP 없이 표면 전체 광택’ 상태에서 실패함을 확인했다. 수정 후 일반/4/5 가중치에서 마스크 지연·제거 시 기본 픽셀 유지, 복구, 명시적 무마스크 비교, 원래 알파 마스크 합성을 검증했다. DOM에서 MatCap만 있고 BUMP가 없는 경우의 보류·표시 수·수동 비교·복구를 검사하며 기존 광택·반사·툰·발광 검사를 유지한다.

### 하이퍼 모드 표시 정정 (2026-10-30)

SecondMap은 파란 상태 효과 텍스처의 정지 합성이다. 일반 조명·유광 개선으로 오해하기 쉬운 ‘표면 보조광’ 명칭을 없애고, 기본적으로 접힌 **캐릭터 상태 효과 실험**으로 분리했다. 원래 기능은 남기되 이전 명칭 아래 저장된 활성 설정은 새 버전에서 OFF로 시작한다. 새로운 명칭으로 직접 선택한 활성 설정만 이후 저장·복원하며, 복원 시 항목을 펼쳐 활성 효과가 숨겨지지 않게 한다. DOM에서 분리·초기 접힘·이전 설정 OFF 이관과 텍스처 연결·설정 저장·누락/복구를 검증했다.

### 14단계: 하이퍼 모드 SecondMap 정지 미리보기 (2026-10-30)

**조명 · 재질 → 하이퍼 모드 표면 보조광 · 정지 미리보기 → 원본 SecondMap 켜기**로 비교한다. 초기에는 꺼져 있으며 선택과 UV 가로·세로 이동을 저장한다. 캐릭터 원본 `GUST_USER_<CHARACTER>.LUA`의 `GAME_UNIT_TEMPLET.m_HyperModeSecondTexture.m_SecondTexture`만 연결한다. 현재 확인한 이세하·이슬비·서유리 원본은 `BD_TILES_HYPER_MODE.DDS`, `m_SecondTexOffSetSpeed={3,3}`이다. 해당 설정은 아이템 유광 타입이나 MatCap과 별개인 캐릭터의 하이퍼 모드 입력이다.

로더 `CW.EXE:0x1410c2216`은 `m_HyperModeSecondTexture`를 읽어 `0x141077c10`에 전달한다. `0x141077c23`은 `m_SecondTexture`, `0x141077c4b`는 두 성분의 `m_SecondTexOffSetSpeed`를 읽는다. 최신 VS는 `v4.xy + cb5[1].xy`를 PS의 `v3.zw`로 전달하고, 최신 PS는 t8 RGB를 샘플링하여 `r2 = GLOW * LightIntensity + SecondMap.rgb`로 더한다. 따라서 SecondMap에는 기본색·툰 계수·조명 색/강도를 다시 곱하지 않는다. 알파를 투명도나 강도로 사용하지 않으며 발광 MRT1과 구분한다.

뷰어는 원본 UV에 수동 오프셋을 더하는 정지 화면만 제공한다. 원본 속도는 출처 정보에 보존하지만 프레임별 애니메이션, 하이퍼 모드 자동 발동·해제, 다른 상태의 SecondMap 교체는 미구현이다. 기본색·발광과 독립된 텍스처 역할/캐시를 사용하고 Repeat로 읽는다. 색 텍스처로 읽는 뷰어의 sRGB 처리와 최종 인게임 색공간 일치는 미검증이다. 캐릭터 설정이 없으면 연결하지 않으며, 잘못된 설정은 사유를 보존한다. 텍스처 누락·출처 중복은 적용을 보류하고 기존 출처 선택 UI에서 확인할 수 있다. NPC에는 연결하지 않는다.

검증: 실제 캐릭터 3종의 원본 정의·이미지 연결, 실제 머리 모델의 효과 ON/UV 이동/OFF 화면, 알파 보존·OFF 정확 복원·번짐/발광 전용 제외를 확인했다. 합성 GPU 검사는 일반/4/5 가중치, 툰/얼굴 SDF, 실제 발광 동시 합성, 조명 강도 0에서도 유지되는 가산식, SecondMap 알파 무시, UV 이동/Repeat, 무관한 표면 제외를 포함한다. DOM에서는 독립 텍스처 캐시·설정 저장·모델 재로딩·누락/복구·모델 지우기를 검증한다. 캡처는 `diagnostics/second-20261030/`에 보관한다. EXT B 표면 가산은 계속 미구현이다.

### 13단계: 원거리·근거리 조명 강도 수동 비교 (2026-10-30)

**조명 · 재질 → 원본 툰 음영 켜기 → 조명 선택 → 원거리 → 근거리 조명 강도 · 수동 비교**에서 혼합 비율을 조절한다. 초기값 0%는 기존 원거리 강도이며, 100%는 원본 근거리 강도다. 선택을 저장하며 원본 조명 출처의 값은 바꾸지 않는다. `CW.EXE:0x1415fb2f0`에서 확인한 `far*(1-weight)+near*weight`를 사용한다. 게임이 weight를 설정하는 조건·거리 변환은 미확정이므로 카메라 줌과 자동 연동하지 않는다.

지역 프로필에도 명시된 `m_fLightIntensityNear`만 전달한다. 근거리 0은 유효하며, 누락·음수 값은 비교에 사용하지 않는다. 근거리 수치가 없는 프로필로 바꾸면 기존 원거리 강도로 즉시 복귀한다. 툰·얼굴 SDF·GLOW가 같은 비교 강도를 사용하며, EXT 반사·rim의 별도 계수와 발광·번짐 광원은 변경하지 않는다. 기존 색상 비교 모드에는 적용하지 않는다. 조명을 읽지 못하면 이전 효과를 비활성화하고, 복구하면 저장된 선택으로 다시 비교한다.

평화의 광장 황혼은 0.9→1.2, 몽마르트르 황혼은 0.911→0.983이다. 실제 이세하·이슬비·서유리 기본 머리 3종에 두 지역 조명을 적용하여 원거리·중간·근거리 픽셀 변화, 알파 보존, 원거리 정확 복원을 검사한다. 합성 GPU 검사에서는 툰·얼굴 SDF·GLOW 동시 합성, 발광/번짐 분리, 0·누락·잘못된 값, 선택 저장·모델 재로딩·실패/복구·OFF를 검증한다. 캡처는 `diagnostics/near-20261030/`에 보관한다.

## 2026-10-29 11단계: 원본 테두리광(rim) 합성

**조명 · 재질 → 원본 툰 음영 켜기 → 지역 조명 선택 → 원본 테두리광 포함 (근사)**으로 비교한다. 최초에는 꺼져 있고 이후 선택을 저장한다. EXT·BUMP·MatCap 없이 툰 표면에 적용하며, 얼굴은 **얼굴 SDF 음영 포함**을 함께 켜서 비교한다. 일반 NPC·눈동자 등 연결이 없는 재질에는 적용하지 않는다. 원본 폭·강도 중 하나라도 누락되면 기본값을 만들지 않는다. 반사 수치 없이 rim 수치만 있는 지역 입력도 구분해 보존한다.

현재 비교 목록의 평화의 광장·몽마르트르(황혼)는 원본 강도가 모두 **0**이다. 체크해도 기존 픽셀을 유지하며, 화면에 **원본 테두리광 강도 0 · 화면 변화 없음**을 표시한다. 이를 임의 강도 1 등으로 바꾸지 않는다. 툰·얼굴 텍스처가 없거나 해당 음영을 켜지 않았다면 준비 상태를 안내한다. 지역 자동 선택·착용 조건·카메라와 광원의 게임 내 배치·최종 인게임 외형은 여전히 미검증이다.

최신 PS의 `cb1[9].xy`는 폭과 강도이며 `cb2[13].xyz`는 카메라의 정규화된 전방 방향이다. 식은 `rim = clamp(1 - abs(dot(N,V))*width,0,1) * max(-dot(L,V),0) * power`이다. N은 보간된 기하 법선, V는 카메라 전방 방향, L은 일반 LightDir이다. 픽셀별 시선 벡터나 BUMP 법선으로 대체하지 않는다. 폭 0은 첫 항을 1로 만들며 꺼짐을 의미하지 않는다. 강도 0은 기여가 없다.

일반 표면은 `toon * surface * rim`을 더하고, 얼굴은 SDF로 만든 표면색에 `rim`을 곱해 더한다. 조명 RGB·조명 강도를 다시 곱하지 않으며, GLOW·XET 발광은 이후에 독립적으로 합성한다. 알파·투명도·형상은 보존하고 발광 전용 패스·번짐 광원에서 제외한다. 카메라 전방은 현재 viewMatrix의 회전을 역변환해 매 프레임 반영한다. 원본 업로드는 `0x1415feb52`~`0x1415feb73`, ViewDir 생성은 `0x14159afbf` 이후에서 확인했다.

합성 GPU 검사는 채널별 수치식, 카메라 회전·광원 방향 조건, 폭 0/강도 0의 구분, 일반/4/5개 가중치 스키닝, 얼굴 SDF·발광 동시 합성, 알파 보존·OFF 복원·설정 저장·조명 로딩 실패와 복구를 포함한다. 실제 기본 머리 3종·지역 2종에서는 원본 강도 0이 픽셀을 바꾸지 않는지 확인했다. 별도로 **진단용 강도 1**을 넣어 실제 형상의 카메라 방향 연동·OFF 복원·번짐 제외를 검증했으며, 이 값은 원본 조명이나 사용자 설정으로 제공하지 않는다. `probe-power1` 캡처는 인게임 외형 증거가 아니다. 근거는 `diagnostics/rim-source-20261029.txt`, 캡처는 `diagnostics/rim-20261029/`에 보관한다.

## 2026-10-29 8단계: 광택의 정점 접선 기반 굴곡 방향

원본 `CW_DEFAULT.VS.CSO`는 tangent·bitangent 입력(v7/v8)을 법선과 함께 스킨 변형하고 정규화해 PS로 보낸다. `CW_CARTOONLIGHT.PS.CSO`는 보간된 세 축을 각각 정규화한 뒤 BUMP RGB를 이 기저로 변환한다. 기존 미리보기는 화면 위치·UV의 삼각형 미분으로 tangent·bitangent를 구성해, 매끄러운 정점 법선과 접선이 수직을 이루지 않을 수 있었다.

## 2026-10-29 6단계: 원본 GLOW 표면 보조광

**조명 · 재질 → 원본 툰 음영 켜기 → 의상 조명 선택 → 원본 GLOW 표면 보조광 포함 (근사)**으로 사용한다. 최초에는 꺼져 있으며 이후 선택은 저장한다. 연결 개수·준비 상태·원래 텍스처와 보조 이미지 이름을 표시한다. 대응하는 맵이 없는 아바타·일반 NPC에는 효과를 만들지 않는다.

### MatCap과 반사

최신 CSO의 t13/s12는 `g_tMatCapMap`이다. t1 normal 입력의 RGB 중 하나라도 양수일 때만 이 분기로 진입한다. normal RGB를 [-1,1]로 복원하고 TBN 및 행렬 변환·정규화를 거친 XY를 `(0.5,-0.5)`로 곱하고 0.5를 더해 좌표를 만든다. MatCap RGB에 **normal 맵의 알파**를 곱해 기본색에 더하고 saturate한다. 이어 별도 반사색·지수에 의한 반사를 같은 알파로 제어한다.

정적 실행 파일의 `0x141747e23`은 XET 보조 텍스처를 MatCap 바인딩 함수 `0x1415fee60`에 전달한다. `0x1415fb540`은 원본 normal 리소스 유무도 검사한 뒤 별도 반사 수치를 설정한다. 따라서 m_MultiTexName만 있다는 이유로 이 분기의 활성·기여도를 결정할 수 없다. normal의 자동 연결 규칙, tangent/bitangent 및 런타임 행렬 조건은 아직 완전히 확인하지 않았다.

이전 `diffuse * sphereMap * 0.35`는 이 식과 다르며 원본 근거가 없는 계수였다. 피부에 적용되던 해당 코드를 제거했다. API의 기존 skin-sphere 항목은 출처 호환성을 위해 남기되 `status=unsupported`로 반환하고 렌더러에서는 설치하지 않는다.

### 툰·마스크·염색

최신 VS는 원본 법선과 정규화된 `g_v4DLightDir`의 내적을 툰 UV 두 성분에 넣는다. PS는 이 좌표로 툰 맵을 읽고 cartoon power를 곱해 saturate한다. half-Lambert나 임의의 램프로 대체하지 않았다. 아이템별 툰 변경표만으로 표면의 기본 툰 할당, 게임 조명 방향·세기까지 확정할 수 없다. 일부 변경 대상 이름은 카탈로그의 BMP로도 존재하지 않는다.

구형 FX의 기본 조명 분기는 mask.r을 알파에 곱하지만 최신 Cartoon CSO에는 t6 mask 샘플이 없다. XET의 mask를 모든 표면의 투명도에 곱하면 원본 조건을 무시하게 된다.

최신 염색 분기는 구형 HLSL의 단순 R/G/B 가중합과 다르다. R과 (1-R), B 및 알파를 이용하는 saturate·합성 연산이 있으며 normal 분기와도 배타적이다. 마스크의 채널·실제 염색색·분기 활성 조건을 함께 확인해야 하므로 임의의 염색색을 넣지 않았다.

### 발광

최신 PS는 원본 UV의 t12를 읽고 EmissiveColor와 strength 두 성분을 곱해 **별도 MRT1**에 기록한다. XET의 색·강도 연결은 실행 파일의 `0x141747ef6`~`0x141747f15`에서도 확인된다. 알파 및 게임 후처리·bloom은 별도의 경로다.

현재 미리보기는 `emissiveMap.rgb * XET.color.rgb * XET.strength`를 같은 표면에 더한다. 임의 강도 계수는 없다. UV 반복, 뒤집기, 기본색과 독립된 텍스처 캐시를 사용한다. 게임의 별도 발광 타깃·후처리·두 번째 런타임 strength·색공간과의 일치는 검증하지 않았으므로 **근사 미리보기**다. 알파에는 발광색이나 발광 맵 알파를 곱하지 않으며 기존 ALPHA·눈동자 처리와 alphaTest를 유지한다.

## 이슬라 리트모의 작은 변화에 대한 판단

하피 A타입 신발(25986, `ROGUE:1307012414:0`)의 XET는 피부 표면에 MAT_209_SKIN.PNG를 지정한다. 이 128×128 원본의 채널 범위는 R 0~82, G 0~67, B 0~51, A 255다. 대부분 어둡고 하이라이트가 좁다. 이전 구현은 이를 sRGB에서 선형 변환한 뒤 기본색 및 0.35를 곱했으므로, 샘플 영역에 따라 기존 최대 2/255 수준의 변화가 생긴다는 설명은 가능하다.

그러나 이것은 **기존 근사식에서의 작은 변화**에 대한 설명이다. 인게임 효과가 원래 미세하다는 증거가 아니다. 최신 셰이더가 요구하는 normal/alpha 및 조명 입력을 확인하기 전에는 단일 신발의 MatCap 강도를 단정할 수 없다. 현재는 그 작은 변화를 재현 성공으로 취급하지 않는다.

[공식 아틀리에 안내](https://www.naddic.co.kr/ko/game/cls/notice/detail?contentNo=1230)는 이슬라 리트모 라이트에 7부위 조건을 명시한다. 신발 하나의 XET 보조 재질과 세트 광원효과를 동일시할 수 없다. [공식 GM노트](https://www.naddic.co.kr/ko/game/cls/gmNote/detail?contentNo=1232)의 자료도 동일 캐릭터·타입·카메라·조명에서의 MatCap ON/OFF 기준 화면은 아니므로 수치 대조의 정답으로 사용하지 않았다.

### 2026-10-28 1단계: 선택형 MatCap 미리보기

API의 새 `matcap_preview`는 기존 발광 `material_preview` 및 미지원 `skin-sphere`와 분리한다. 렌더러는 스키닝 후 뷰 공간의 정점 법선을 정규화하고 XY에 `(0.5,-0.5)`를 곱한 뒤 0.5를 더해 MatCap 좌표를 만든다. 선형 공간에서 `clamp(기본색 + MatCap.rgb * 사용자 강도, 0, 1)`로 합성하며 그 뒤에 발광을 더한다. 원본 normal/alpha의 자동 연결·런타임 반사 분기는 다음 단계다. 현재 광택 마스크를 1로 보는 근사이므로 게임보다 넓거나 밝게 적용될 수 있다. 기본색·알파는 바꾸지 않고 OFF/강도 0으로 같은 픽셀을 복원한다. MatCap GPU 텍스처는 기본색·발광과 분리하고 가장자리 고정(ClampToEdge)을 사용한다.

실제 미래 홀리 나이트 바니 유광 상의·하의·신발 3부위로 앞·옆·뒤 표시, 알파 보존, OFF/0 복원을 Chromium에서 검증했다. 합성 데이터는 색상 수치식, 무관한 표면 격리, 4개/5개 가중치 스키닝, 발광 합성 및 발광 패스 격리, 로딩/개별 제외/설정 유지/누락/초기화를 검증한다. 실제 캡처는 로컬 `diagnostics/matcap-20261028/`에 보관한다. 이 검증은 게임 화면과의 일치를 뜻하지 않는다.

### 2026-10-28 조명·유광 재확인 (1단계 구현 전)

현재 조명 기능은 원본 프리셋을 읽어 기본색을 변조하는 수치 비교까지 구현되어 있다. 게임 조명 재현은 미구현이다. `MeshBasicMaterial`에 추가한 비교 셰이더에는 게임의 툰 맵 샘플링·MatCap·반사 및 세트 조건 판정이 없다. 기존 자동 테스트 통과는 이 비교식의 동작을 확인하며, 인게임과의 외형 일치를 입증하지 않는다. 같은 조건의 게임 실행 화면과 픽셀 대조는 수행하지 않았다.

로컬 원본에서 읽은 프리셋 7개 중 황천의 사자(`CVN_COSTUME_UNIQUE_NETHERWORLD:211`)는 색 `(0.3, 0.3, 0.3, 1)`, 방향 `(-30, 10, -100)`, 강도 `1.024999976158142`다. 현재 식에서는 기본 비교 강도 0.5일 때 광원 방향을 정면으로 받는 표면의 선형 기본색이 약 0.654배가 된다. 이는 광택을 생성하지 않고 텍스처를 방향별로 어둡게 만드는 동작이므로, 사용자가 보고한 찰흙 같은 외형과 연결될 수 있다. 흰색·강도 1인 서니데이 어드벤처와 이슬라 리트모는 현재 식에서 항상 배율 1이므로 선택해도 기본색에 변화가 없다. 추가 수치 1.5는 읽기만 하고 사용하지 않는다.

유광은 조명·발광 스위치와 별개의 재질 효과다. 설치 데이터의 이름에 유광이 포함된 아이템 정의 90개를 확인했다(등급별 중복을 포함한 수치). 실제 미래 홀리 나이트 바니 상의의 A타입과 유광타입은 같은 X 모델(엔트리 264757)과 기본색 텍스처를 사용한다. 유광타입의 XET는 `m_MultiTexName=Mat_cloth_158.png`를 지정하며, API는 해당 이미지(엔트리 367466)까지 찾지만 `material_report.unsupported`에 `m_MultiTexName`을 기록한다. 현재 렌더러에는 이 입력을 표시하는 경로가 없어 이 표본은 A타입과 같은 기본색으로 표시된다.

당시 뷰어에서는 의상별·부위별 목록에서 유광타입 아이템을 선택해도 광택을 적용할 수 없었다. 위 1단계에서 선택형 근사 미리보기를 추가했다. 인게임 재현을 위해서는 원본 normal 텍스처 및 알파의 연결 규칙, TBN·MatCap 좌표와 반사 분기를 확정해야 한다. 세트 조명은 별도로 툰 할당·런타임 조명 값과 착용/옷장 조건을 연결해야 한다. 이후 같은 캐릭터·타입·자세·카메라의 인게임 기준 화면으로 검증해야 한다.

이번 조사는 렌더링 동작을 변경하지 않았다. 조사 메타데이터와 실제 A/B/유광 장면의 재질 응답은 로컬 `diagnostics/lighting-gloss-audit-20261028.json`에 보관한다. WebGL 회귀 검사에는 흰색·강도 1의 무변화, 황천 원본 값에 따른 어두워짐, OFF 시 원래 픽셀 복원을 추가했다.

### 선택형 의상 조명 비교

`조명 · 발광`의 의상 조명은 `LIGHT_CONVERT_TEMPLET.NTF`/`LIGHT_CONVERT_DATA.NTF` 및 `SET_ITEM_EFFECT_TEMPLET.NTF`/`SET_ITEM_UNIT_LIGHT_DATA.NTF`에서 색·방향·강도를 읽는 별도 비교 기능이다. NTF의 type 9 강도는 IEEE 754 float로 해석하며, 한국어 이름은 원본 문자열 키로 연결한다. 착용 조건을 판정한 인게임 조명 자동 적용이라고 표시하지 않는다.

초기 구현은 기본색에 Lambert 항을 곱해 이미 음영이 그려진 텍스처를 다시 어둡게 만들었다. 현재는 `mix(1, color.rgb * intensity, max(dot(worldNormal, lightDirection), 0) * influence)`를 기본색에 곱하는 **수치 비교**로 제한하고 기본 비교 강도를 0.5로 둔다. 게임 좌표의 Z축을 뷰어 좌표에 맞춰 뒤집으며, 일반/다중 가중치 스키닝 법선도 변환한다. 발광의 가산식은 이 계산 이후에 독립적으로 적용한다. 기존 게임 툰 셰이더의 재현이나 미확인 MatCap 분기의 활성화가 아니다. `near_intensity`와 별도 추가 수치는 출처에 보존하지만 확인하지 못한 런타임 보간·후처리에는 사용하지 않는다.

현재 아바타의 확인된 발광 연결은 아이템·원본 텍스처별로 표시하고 각각 제외할 수 있다. 전체 발광 스위치는 이 개별 제외 선택을 유지하며, 조명 OFF는 기본색·발광·투명도를 원래 값으로 복원한다.

### 발광 확인과 선택적 번짐

기본색과 독립된 발광 패스에서 켜진 발광 텍스처만 렌더링한다. 나머지 아바타 표면은 원래 알파·깊이를 유지하는 검은 가림막으로 남긴다. 따라서 흰 기본색이 광원으로 오인되거나 다른 아바타 메시 뒤의 발광이 새어 나오지 않는다. 배경·모션 효과·보조 장식은 이 패스에서 제외한다. 별도 발광 타깃을 가로·세로 Gaussian blur한 뒤 선형 공간에서 원래 화면과 합성한다. 원본 게임 후처리 계수나 런타임 bloom 재현으로 주장하지 않는다.

발광 입력이 전혀 없는 모델도 `발광만 보기`에서는 검게 표시한다. 이전에는 준비된 발광 맵이 없으면 일반 렌더로 돌아가 기본색·MatCap이 발광처럼 보일 수 있었으나 이를 수정하고, 광택만 있는 모델로 회귀 검사한다.

`발광만 보기`와 확인용 밝기는 실제 발광 부위 확인을 위한 진단 화면이다. 확인용 밝기는 기본 화면의 발광 강도를 바꾸지 않는다. 기본 결과의 일괄 미지원 경고는 제거하고, 미지원 입력은 해당 재질의 상세 정보에 남긴다. 설치된 휠 오브 트리니티 6부위와 리어윙의 실제 모델·텍스처로 표면/번짐/발광만/발광 OFF를 비교하는 회귀 테스트를 추가했다. 의상의 얇은 장식선 발광과 리어윙 홈의 발광을 구분해서 확인한다.
