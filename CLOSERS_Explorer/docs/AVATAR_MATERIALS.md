# 아바타 재질 조사와 표시 범위

2026-10-24 로컬 게임 원본을 읽어 검증했다. 원본 CMF, CW.EXE, 기존 추출 에셋은 수정하지 않는다.

## 적용 범위

| 입력 | 확인한 의미 | 현재 표시 |
| --- | --- | --- |
| X Material의 power, specular RGB, emissive RGB | X 파일에 보관된 원본 수치 | API에 보존. 게임의 활성 조건 확인 없이 조명 값으로 적용하지 않음 |
| XET m_mapEmissiveMaterial | OrgTexName별 EmissiveTexName, RGBA, fEmissiveStrength | 선택한 아이템의 원본 텍스처에만 발광 미리보기 연결 |
| m_MultiTexName | XET 렌더 경로에서 MatCap으로 바인딩 | 선택형 광택 근사 미리보기. 게임의 전체 재질 분기는 미지원 |
| m_MaskTexName | XET 렌더 경로에서 g_tMaskMap으로 바인딩 | 출처 표시. 모든 재질에 알파 마스크로 적용하지 않음 |
| m_strDyeingMaskTexName | 별도 염색 입력 | 출처 표시, 효과 미적용 |
| m_mapToonTexChange | 아이템의 원본 툰 이름에서 대상 툰 이름으로 변경 | 변경표 보존·표시, 효과 미적용 |
| SpecularColor / SpecularPower | 별도 MatCap 반사 설정의 입력 | normal/MatCap이 준비된 표면에 선택형 반사 미리보기. 확인용 카메라 광원 사용 |
| 피부 이외 보조 재질 | m_MultiTexName 입력도 아이템별로 보존 | 명시된 MatCap 입력에만 광택 근사 미리보기 제공 |

미지원은 실패한 기본색 로딩과 구분한다. 발광 텍스처가 없거나 출처가 중복이면 기본색과 모델을 유지하고 확인할 항목을 안내한다. 중복 XET에서 새로 보존한 툰·발광 블록이 다르면 해당 효과만 보류한다. 기본색 변경표 자체가 충돌한 경우는 기존 오류 처리를 유지한다.

## 원본 대조

동봉 FX/HLSL과 실제 CSO의 내용이 다르다. `CW_CARTOONLIGHT.PS.CSO`와 `CW_DEFAULT.VS.CSO`를 Windows `D3DDisassemble`로 읽어 최신 경로를 조사했다. 게임 코드는 실행하지 않았다.

- `NKXMESH_RI_BASIC.FX` SHA-256: `a57c8d6339871e75da6bc79868ec293cd8eca5b879df7fcf537cdc16d087cb78`
- `NKXMESH_RI_BASIC_CARTOONLIGHT_PS.HLSL`: `9cf7a95ec2d7e151fd87fed0d43fe57c0223d5e1f18f6f25287fafb9c3f01498`
- `NKXMESH_RI_BASIC_VS.HLSL`: `53a70237f63ac6992a6019d07cb6f5e7954fdf19509d754e7ba99f7d27597b9c`

원본별 CMF·순번·바이트 해시는 아래 감사 스크립트가 기록한다. 로컬 조사본은 `diagnostics/material-source/`, 메타데이터는 `diagnostics/material-audit.json`에 있다. 게임 셰이더 본문은 저장소에 포함하지 않는다.

### MatCap과 반사

최신 CSO의 t13/s12는 `g_tMatCapMap`이다. t1 normal 입력의 RGB 중 하나라도 양수일 때만 이 분기로 진입한다. normal RGB를 [-1,1]로 복원하고 TBN 및 행렬 변환·정규화를 거친 XY를 `(0.5,-0.5)`로 곱하고 0.5를 더해 좌표를 만든다. MatCap RGB에 **normal 맵의 알파**를 곱해 기본색에 더하고 saturate한다. 이어 별도 반사색·지수에 의한 반사를 같은 알파로 제어한다.

정적 실행 파일의 `0x141747e23`은 XET 보조 텍스처를 MatCap 바인딩 함수 `0x1415fee60`에 전달한다. `0x1415fb540`은 원본 normal 리소스 유무도 검사한 뒤 별도 반사 수치를 설정한다. 따라서 m_MultiTexName만 있다는 이유로 이 분기의 활성·기여도를 결정할 수 없다. normal의 자동 연결 규칙, tangent/bitangent 및 런타임 행렬 조건은 아직 완전히 확인하지 않았다.

이전 `diffuse * sphereMap * 0.35`는 이 식과 다르며 원본 근거가 없는 계수였다. 피부에 적용되던 해당 코드를 제거했다. API의 기존 skin-sphere 항목은 출처 호환성을 위해 남기되 `status=unsupported`로 반환하고 렌더러에서는 설치하지 않는다.

### 툰·마스크·염색

최신 VS는 원본 법선과 정규화된 `g_v4DLightDir`의 내적을 툰 UV 두 성분에 넣는다. PS는 이 좌표로 툰 맵을 읽고 cartoon power를 곱해 saturate한다. half-Lambert나 임의의 램프로 대체하지 않았다. 아이템별 툰 변경표만으로 표면의 기본 툰 할당, 게임 조명 방향·세기까지 확정할 수 없다. 일부 변경 대상 이름은 카탈로그의 BMP로도 존재하지 않는다.

구형 FX의 기본 조명 분기는 mask.r을 알파에 곱하지만 최신 Cartoon CSO에는 t6 mask 샘플이 없다. XET의 mask를 모든 표면의 투명도에 곱하면 원본 조건을 무시하게 된다.

최신 염색 분기는 구형 HLSL의 단순 R/G/B 가중합과 다르다. R과 (1-R), B 및 알파를 이용하는 saturate·합성 연산이 있으며 normal 분기와도 배타적이다. 마스크의 채널·실제 염색색·분기 활성 조건을 함께 확인해야 하므로 임의의 염색색을 넣지 않았다.

### 발광

최신 PS는 원본 UV의 t12를 읽고 EmissiveColor와 strength 두 성분을 곱해 **별도 MRT1**에 기록한다. XET의 색·강도 연결은 실행 파일의 `0x141747ef6`~`0x141747f15`에서도 확인된다. 알파 및 게임 후처리·bloom은 별도의 경로다.

현재 미리보기는 `emissiveMap.rgb * XET.color.rgb * XET.strength`를 같은 표면에 더한다. 임의 강도 계수는 없다. UV 반복, 뒤집기, 기본색과 독립된 텍스처 캐시를 사용한다. 게임의 별도 발광 타깃·후처리·두 번째 런타임 strength·색공간과의 일치는 검증하지 않았으므로 **근사 미리보기**다. 알파에는 발광색이나 발광 맵 알파를 곱하지 않으며 기존 ALPHA·눈동자 처리와 alphaTest를 유지한다.

## 이슬라 리트모의 작은 변화에 대한 판단

하피 A타입 신발(25986, `ROGUE:1307012414:0`)의 XET는 피부 표면에 MAT_209_SKIN.PNG를 지정한다. 이 128×128 원본의 채널 범위는 R 0~82, G 0~67, B 0~51, A 255다. 대부분 어둡고 하이라이트가 좁다. 이전 구현은 이를 sRGB에서 선형 변환한 뒤 기본색 및 0.35를 곱했으므로, 샘플 영역에 따라 기존 최대 2/255 수준의 변화가 생긴다는 설명은 가능하다.

그러나 이것은 **기존 근사식에서의 작은 변화**에 대한 설명이다. 인게임 효과가 원래 미세하다는 증거가 아니다. 최신 셰이더가 요구하는 normal/alpha 및 조명 입력을 확인하기 전에는 단일 신발의 MatCap 강도를 단정할 수 없다. 현재는 그 작은 변화를 재현 성공으로 취급하지 않는다.

[공식 아틀리에 안내](https://www.naddic.co.kr/ko/game/cls/notice/detail?contentNo=1230)는 이슬라 리트모 라이트에 7부위 조건을 명시한다. 신발 하나의 XET 보조 재질과 세트 광원효과를 동일시할 수 없다. [공식 GM노트](https://www.naddic.co.kr/ko/game/cls/gmNote/detail?contentNo=1232)의 자료도 동일 캐릭터·타입·카메라·조명에서의 MatCap ON/OFF 기준 화면은 아니므로 수치 대조의 정답으로 사용하지 않았다.

## 검증과 재실행

### 2026-10-28 3단계: 원본 반사색·반사 지수

**조명 · 재질 → 광택 켜기 → 원본 표면 굴곡·광택 마스크 사용 → 원본 반사색·반사 지수 사용 (근사)**에서 별도 반사를 켠다. 반사 설정은 최초에 꺼져 있고 이후 선택을 저장한다. 광택 강도와 표면별 제외를 함께 따르며, normal/MatCap 이미지가 누락·중복되거나 원본 normal 사용을 끄면 반사도 보류한다. X Material의 일반 specular/power를 XET 반사 수치로 대신 쓰지 않는다.

XET에 `SpecularColor`와 `SpecularPower`가 모두 유효하게 지정된 표면에만 `matcap_preview.specular`를 제공한다. 설치 원본에서 이 입력을 가진 XET 정의 205개를 확인했다. 실행 파일의 `0x141747e72`~`0x141747e8b`는 표면 normal·MatCap과 별도 반사 설정을 `0x1415fb540`으로 넘기며, 이 함수는 normal 리소스 슬롯 `0x128`이 있을 때만 색 4성분·지수를 설정한다. 최신 `CW_CARTOONLIGHT.PS.CSO`는 `cb5[25].rgb` 반사색과 `cb5[26].x` 지수를 사용한다.

원본 반사식은 `clamp(표면색 + SpecularColor.rgb * pow(clamp(dot(N, normalize(L+V)),0,1), SpecularPower) * normal.a,0,1)`이다. 반사색의 네 번째 성분은 광택 마스크나 투명도로 사용하지 않는다. viewer는 기존 MatCap 합성 뒤에 이 반사를 적용하고 발광은 마지막에 더한다. 게임 실행 중의 `g_v4LightPos`는 아직 연결하지 못했으므로 **카메라 위치의 확인용 광원**을 사용한다. 따라서 `L=V`, 반각 벡터는 시선 방향과 같으며 별도 거리 감쇠·임의 강도 배율은 없다. 사용자의 광택 강도(0~1)만 MatCap·반사에 함께 적용한다. 0인 지수의 경계는 일정한 반사 가중치 1로 정의한다. 툰 조명 프리셋의 방향을 위치로 오인해 대입하지 않는다.

원본 TBN은 여전히 화면 미분으로 근사하고, 게임의 광원 위치·툰·후처리는 미연결이다. 이 단계는 원본 재질 반사 수치를 비교하는 기능이며 인게임 외형 일치를 보장하지 않는다. `material_report.unsupported`는 게임 전체 재현의 미지원 입력을 보존하고, 별도 미리보기 상태는 `matcap_preview.specular.status=approximate`, `light_source=viewer-camera`로 표시한다.

실제 미래 아우라 픽시즈 A타입 상의·하의·신발에 지수 300/500/800, 반사색 `(1,1,1,1)`이 연결되는 것을 확인했다. 상의 엔트리 401997/normal 401999, 하의 402003/normal 401872, 신발 402004/normal 401876이다. Chromium에서 앞·옆·뒤 반사 유무·알파 보존·OFF 복원을 검증하고 `diagnostics/specular-20261028/`에 캡처를 남겼다. 원본 수치·연결 응답은 `diagnostics/specular-audit-20261028.json`, `specular-scenes-20261028.json`에 기록한다. 합성 WebGL 검사는 채널별 색·지수·알파 수치식, 지수 증가 시 하이라이트 축소, 일반/5개 가중치 스키닝, 다른 표면 격리, OFF/0 복원, 원본 normal 끄기·이미지 누락·개별 제외·선택 유지 및 발광 패스 격리를 포함한다.

### 2026-10-28 2단계: 원본 normal RGB·알파 연결

게임 실행 파일의 리소스 로더를 정적으로 대조해 `_BUMP` 연결을 확인했다. `0x14171836a`는 타입 4로 `0x1417156a0`을 호출하고, 이 함수의 `0x141715738`~`0x1417157da`는 확장자 앞에 `_BUMP`를 삽입한다. `0x1417151d3`의 리소스 슬롯은 `0x108 + 타입*8`이므로 타입 4는 `0x128`이며, 기존 반사 설정 함수 `0x1415fb59a`가 검사하는 normal 리소스와 일치한다. 조사한 CW.EXE SHA-256은 `8ea0ce3ba885f3044103c8e071e627b52a0e93cf56cc44b0e03dffed7c440283`다. 로컬 근거는 `diagnostics/matcap-normal-source-20261028.txt`에 남긴다.

현재 선택한 기본색 텍스처의 마지막 4글자 확장자 앞에 `_BUMP`를 삽입한 **정확한 이름**만 조회한다. XET 기본색 변경 이후의 텍스처에 연결하고, 이미지 출처가 중복이면 자동 선택하지 않는다. 찾지 못하면 1단계 정점 법선 근사를 유지한다. normal 데이터는 sRGB 변환 없이 읽고, 기본색 UV의 반복·방향을 유지한다. 원본 RGB가 모두 0이면 MatCap 기여를 0으로 하고, 나머지는 RGB를 [-1,1]로 복원해 법선으로 사용한다. 알파는 기본색 투명도가 아닌 광택 가중치다.

원본 tangent/bitangent를 아직 파싱하지 않으므로 화면 위치·UV 미분으로 TBN을 구성하는 근사다. 퇴화 UV에서는 정점 법선으로 돌아가며 알파 마스크는 유지한다. 기본적으로 원본 굴곡·마스크를 사용하고 **원본 표면 굴곡·광택 마스크 사용** 체크로 1단계와 비교한다. 별도 `SpecularColor/SpecularPower` 반사, 게임 조명·후처리는 여전히 미지원이다.

미래 홀리 나이트 바니 상의의 `301791704_GUST_USER_REAPER_CLOTH_158_A_EP_AVATAR_DEFENCE_UPBODY_BUMP.TGA`(엔트리 365449)는 512×512이며 알파가 0~57이다. 모든 표면에 가중치 1을 주던 1단계보다 원본 광택 가중치가 크게 낮다. 상의·하의·신발의 실제 normal/MatCap을 함께 불러 앞·옆·뒤에서 원본 마스크 적용/미적용, OFF/0 복원을 검증했다. 캡처는 `diagnostics/matcap-normal-20261028/`에 보관한다. 합성 검사에서는 알파 0/128, RGB 0, 데이터 색공간, 스키닝 TBN, 텍스처 역할 격리·중복 출처도 확인한다.

### 2026-10-28 1단계: 선택형 MatCap 미리보기

**조명 · 재질 → 광택 켜기 (근사)**에서 선택한 아이템의 XET에 연결된 MatCap을 확인한다. 최초에는 꺼져 있으며 전체 켜기·강도(0~1)·아이템/원본 표면별 제외를 별도로 저장한다. 발광 토글과 독립적이고, 광택은 발광 전용 패스 및 번짐에 들어가지 않는다. 파일 단독 보기나 XET에 해당 표면 연결이 없으면 설치하지 않는다. 누락·중복 이미지는 자동 연결하지 않고 기본 재질을 유지한다.

API의 새 `matcap_preview`는 기존 발광 `material_preview` 및 미지원 `skin-sphere`와 분리한다. 렌더러는 스키닝 후 뷰 공간의 정점 법선을 정규화하고 XY에 `(0.5,-0.5)`를 곱한 뒤 0.5를 더해 MatCap 좌표를 만든다. 선형 공간에서 `clamp(기본색 + MatCap.rgb * 사용자 강도, 0, 1)`로 합성하며 그 뒤에 발광을 더한다. 원본 normal/alpha의 자동 연결·런타임 반사 분기는 다음 단계다. 현재 광택 마스크를 1로 보는 근사이므로 게임보다 넓거나 밝게 적용될 수 있다. 기본색·알파는 바꾸지 않고 OFF/강도 0으로 같은 픽셀을 복원한다. MatCap GPU 텍스처는 기본색·발광과 분리하고 가장자리 고정(ClampToEdge)을 사용한다.

실제 미래 홀리 나이트 바니 유광 상의·하의·신발 3부위로 앞·옆·뒤 표시, 알파 보존, OFF/0 복원을 Chromium에서 검증했다. 합성 데이터는 색상 수치식, 무관한 표면 격리, 4개/5개 가중치 스키닝, 발광 합성 및 발광 패스 격리, 로딩/개별 제외/설정 유지/누락/초기화를 검증한다. 실제 캡처는 로컬 `diagnostics/matcap-20261028/`에 보관한다. 이 검증은 게임 화면과의 일치를 뜻하지 않는다.

### 2026-10-28 조명·유광 재확인 (1단계 구현 전)

현재 조명 기능은 원본 프리셋을 읽어 기본색을 변조하는 수치 비교까지 구현되어 있다. 게임 조명 재현은 미구현이다. `MeshBasicMaterial`에 추가한 비교 셰이더에는 게임의 툰 맵 샘플링·MatCap·반사 및 세트 조건 판정이 없다. 기존 자동 테스트 통과는 이 비교식의 동작을 확인하며, 인게임과의 외형 일치를 입증하지 않는다. 같은 조건의 게임 실행 화면과 픽셀 대조는 수행하지 않았다.

로컬 원본에서 읽은 프리셋 7개 중 황천의 사자(`CVN_COSTUME_UNIQUE_NETHERWORLD:211`)는 색 `(0.3, 0.3, 0.3, 1)`, 방향 `(-30, 10, -100)`, 강도 `1.024999976158142`다. 현재 식에서는 기본 비교 강도 0.5일 때 광원 방향을 정면으로 받는 표면의 선형 기본색이 약 0.654배가 된다. 이는 광택을 생성하지 않고 텍스처를 방향별로 어둡게 만드는 동작이므로, 사용자가 보고한 찰흙 같은 외형과 연결될 수 있다. 흰색·강도 1인 서니데이 어드벤처와 이슬라 리트모는 현재 식에서 항상 배율 1이므로 선택해도 기본색에 변화가 없다. 추가 수치 1.5는 읽기만 하고 사용하지 않는다.

유광은 조명·발광 스위치와 별개의 재질 효과다. 설치 데이터의 이름에 유광이 포함된 아이템 정의 90개를 확인했다(등급별 중복을 포함한 수치). 실제 미래 홀리 나이트 바니 상의의 A타입과 유광타입은 같은 X 모델(엔트리 264757)과 기본색 텍스처를 사용한다. 유광타입의 XET는 `m_MultiTexName=Mat_cloth_158.png`를 지정하며, API는 해당 이미지(엔트리 367466)까지 찾지만 `material_report.unsupported`에 `m_MultiTexName`을 기록한다. 현재 렌더러에는 이 입력을 표시하는 경로가 없어 이 표본은 A타입과 같은 기본색으로 표시된다.

### 선택형 의상 조명 비교

`조명 · 발광`의 의상 조명은 `LIGHT_CONVERT_TEMPLET.NTF`/`LIGHT_CONVERT_DATA.NTF` 및 `SET_ITEM_EFFECT_TEMPLET.NTF`/`SET_ITEM_UNIT_LIGHT_DATA.NTF`에서 색·방향·강도를 읽는 별도 비교 기능이다. NTF의 type 9 강도는 IEEE 754 float로 해석하며, 한국어 이름은 원본 문자열 키로 연결한다. 착용 조건을 판정한 인게임 조명 자동 적용이라고 표시하지 않는다.

초기 구현은 기본색에 Lambert 항을 곱해 이미 음영이 그려진 텍스처를 다시 어둡게 만들었다. 현재는 `mix(1, color.rgb * intensity, max(dot(worldNormal, lightDirection), 0) * influence)`를 기본색에 곱하는 **수치 비교**로 제한하고 기본 비교 강도를 0.5로 둔다. 게임 좌표의 Z축을 뷰어 좌표에 맞춰 뒤집으며, 일반/다중 가중치 스키닝 법선도 변환한다. 발광의 가산식은 이 계산 이후에 독립적으로 적용한다. 기존 게임 툰 셰이더의 재현이나 미확인 MatCap 분기의 활성화가 아니다. `near_intensity`와 별도 추가 수치는 출처에 보존하지만 확인하지 못한 런타임 보간·후처리에는 사용하지 않는다.

현재 아바타의 확인된 발광 연결은 아이템·원본 텍스처별로 표시하고 각각 제외할 수 있다. 전체 발광 스위치는 이 개별 제외 선택을 유지하며, 조명 OFF는 기본색·발광·투명도를 원래 값으로 복원한다.

### 발광 확인과 선택적 번짐

기본색과 독립된 발광 패스에서 켜진 발광 텍스처만 렌더링한다. 나머지 아바타 표면은 원래 알파·깊이를 유지하는 검은 가림막으로 남긴다. 따라서 흰 기본색이 광원으로 오인되거나 다른 아바타 메시 뒤의 발광이 새어 나오지 않는다. 배경·모션 효과·보조 장식은 이 패스에서 제외한다. 별도 발광 타깃을 가로·세로 Gaussian blur한 뒤 선형 공간에서 원래 화면과 합성한다. 원본 게임 후처리 계수나 런타임 bloom 재현으로 주장하지 않는다.

발광 입력이 전혀 없는 모델도 `발광만 보기`에서는 검게 표시한다. 이전에는 준비된 발광 맵이 없으면 일반 렌더로 돌아가 기본색·MatCap이 발광처럼 보일 수 있었으나 이를 수정하고, 광택만 있는 모델로 회귀 검사한다.

`발광만 보기`와 확인용 밝기는 실제 발광 부위 확인을 위한 진단 화면이다. 확인용 밝기는 기본 화면의 발광 강도를 바꾸지 않는다. 기본 결과의 일괄 미지원 경고는 제거하고, 미지원 입력은 해당 재질의 상세 정보에 남긴다. 설치된 휠 오브 트리니티 6부위와 리어윙의 실제 모델·텍스처로 표면/번짐/발광만/발광 OFF를 비교하는 회귀 테스트를 추가했다. 의상의 얇은 장식선 발광과 리어윙 홈의 발광을 구분해서 확인한다.
