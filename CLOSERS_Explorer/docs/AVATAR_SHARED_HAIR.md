# 타입 간 공용 헤어

같은 의상의 다른 타입에서 기본 타입 헤어를 함께 쓰는 구성을 지원한다. 2026-10-24 실제 NTF·카탈로그와 브라우저로 A+ 바시티, 몽마의 초상을 확인했다.

## 연결 조건

아이템 단위 목록과 묶음에서 다음 조건을 모두 만족할 때 공용 헤어를 추가한다.

- 캐릭터와 의상 계열·번호가 같고, 대상은 `CLOTH_n_B/C/...` 또는 `RARE_n_B/C/...`다.
- 같은 의상의 A타입에 실제 사용 가능한 헤어 아이템이 있다.
- 헤어 아이템 이름에 `[A타입]` 등 타입 전용 표기가 없다.
- 대상 타입에는 별도 헤어 아이템이 등록되어 있지 않으며, 대상 타입의 헤어 파일도 목록에 없다.
- 대상 의상의 타입 표기가 모호하지 않다. 유광 등 이름으로 표시된 타입도 원래 표기를 유지한다.

타입별 헤어가 등록되어 있는데 파일만 누락된 경우에는 공용으로 대체하지 않는다. 다른 캐릭터·다른 의상 번호, 타입 전용 헤어도 임의로 연결하지 않는다. 공유 관계는 타입 표기가 없는 아이템과 같은 의상 계열을 근거로 한 뷰어 구성 규칙이며, 클라이언트의 모든 세트 구성 로직을 해석했다는 뜻은 아니다.

## 아이템과 외형 보존

공유된 목록 행에는 대상 묶음과 타입을 표시하지만 `appearance_key`, item_id, 원본 XET, 모델·텍스처 출처, 아이콘과 전체 구성 모델은 원래 A타입 헤어의 값을 유지한다. 가상의 B/C 헤어 아이템을 생성하거나 B/C 의상의 XET를 헤어에 덮어쓰지 않는다. 실제 장착 정보의 헤어 출처 역시 원래 아이템으로 남는다.

목록과 묶음에 **A타입 공용 헤어**를 표시하고, 상세에는 A타입과 공유한다는 설명을 붙인다. B타입 검색과 부위 필터에서도 공용 헤어를 찾을 수 있다. 파일 모드는 원본 아이템·파일 목록을 유지하며 가상의 타입 행을 추가하지 않는다.

등급 별칭은 기존처럼 한 선택으로 합친다. 일반/어나더 헤어, 다른 XET 표시, 서로 다른 파일 출처는 별도 선택으로 유지한다. 후보가 여러 개면 자동으로 하나를 고르지 않는다. 일반 헤어의 보조 구성 파일은 함께 불러오고, 어나더로 바꾸면 일반 전용 구성은 제외한다. ALPHA 구성과 선택적인 DYE 동작도 유지한다.

새 영구 캐시나 DB 변경은 추가하지 않았다. 기존 카탈로그·정의 원본 변경 검증을 사용하며, 원본 정의와 캐시 객체를 수정하지 않고 공유 목록 행을 복사해 만든다. 모델 파싱과 GPU 텍스처는 기존의 실제 내용·출처 기준 캐시를 그대로 사용한다. 공유 후보 생성에 별도 SQL 조회를 추가하지 않는다.

## 실제 검증

| 사례 | 확인한 결과 |
| --- | --- |
| 이세하 A+ 바시티 B/C (`STRIKER\|CLOTH_229_B/C`) | 헤어 26881, `STRIKER:1300013011:0`이 두 타입에 자동 포함된다. 등급 별칭은 한 후보로 합쳐진다. |
| 하피 몽마의 초상 B/C (`ROGUE\|CLOTH_232_B/C`) 일반 헤어 | `ROGUE:1307013511:0`의 519836·519839 두 모델을 모두 유지한다. |
| 같은 의상의 어나더 헤어 | `ROGUE:1307013541:0`의 519836 한 모델만 사용한다. 일반/어나더 두 선택이 모두 표시되고 초기 선택은 비어 있다. |

실제 브라우저에서 B→C로 바꿔도 헤어 텍스처 이름과 GPU texture UUID가 유지되는 것을 확인했다. 상의 텍스처는 각각 B/C의 원본 XET 대상을 사용하며 서로 섞이지 않았다. 바시티의 장면은 9,644정점, 몽마 일반 헤어 장면은 14,957정점, 어나더 장면은 14,797정점이었다. 몽마 C 어나더 구성에서 ASTAND 92키·149뼈를 연결해 재생 시간이 진행됐고 브라우저 예외는 없었다.

로컬 자료는 `diagnostics/shared-hair-browser.json`과 `shared-hair-{캐릭터}-{의상코드}-{normal,another}.png`다. 게임 원본과 기존 추출 파일은 변경하지 않았다.

## 자동 테스트와 재실행

관련 자동 테스트 93개가 통과했다. 재실행한 같은 테스트는 합계에 중복 가산하지 않았다.

```powershell
cd CLOSERS_Explorer
python -m unittest discover -s tests -p 'test_shared_hair*.py' # 9
python -m unittest discover -s tests -p 'test_avatar*.py'      # 25
python -m unittest discover -s tests -p 'test_model*.py'       # 42
python -m unittest discover -s tests -p 'test_picker*.py'      # 6
python -m unittest discover -s tests -p 'test_game_names.py'   # 5
python -m unittest discover -s tests -p 'test_material*.py'    # 4
python -m unittest discover -s tests -p 'test_skinning_browser.py' # 1
python -m unittest discover -s tests -p 'test_preview_loading_browser.py' # 1
```

신규 테스트는 공용 연결, 원래 아이템/XET 보존, B/C 재질 격리, 타입 검색·필터, 별도 헤어 등록 우선, 누락 파일을 잘못 대체하지 않는 조건, 중복 출처·어나더 선택, ALPHA/DYE 구성, 다른 캐릭터·의상 차단, 카탈로그 갱신과 실제 UI 전달 값을 다룬다.

실제 데이터가 있는 프로젝트 루트에서 다음 명령으로 브라우저 검증을 재실행할 수 있다. 실행 중인 뷰어와 Chrome이 필요하다. API에서 현재 묶음을 읽고 실제 UI로 선택·착용한 뒤 스크린샷과 검사 결과를 diagnostics에 저장한다.

```powershell
node CLOSERS_Explorer/tests/verify_shared_hair.mjs http://127.0.0.1:8765
```

구현 커밋은 `01dbeaa`이며, 최종 기능을 8765 서버에 반영했다. 반영 후 확인한 포트 소유자는 PID 22124였다. 별도 검증용 8771 서버만 정리했으며 진행 중인 분석·추출 작업을 종료하지 않았다.
