# 원본 조명 착용 조건 진단

2026-10-31. 원본 파일은 읽기만 한다. 현재 기능은 **선택한 장비의 조건 진단과 뷰어 조명 선택**이며, 게임의 조명 자동 활성화 구현 완료를 의미하지 않는다.

## 원본 선택 상태 조회와 뷰어 지정 (2026-10-31 후속)

원본 렌더링 경로에서 `SCT_LIGHT=5`의 **현재 선택 번호**를 조회하는 연결을 확인했다. 조명 템플릿의 그룹 번호로 선택하며, 템플릿이 참조하는 조명 데이터 번호와 다르다. 예를 들어 선택 번호 1411은 조명 데이터 3, 211은 데이터 2에 연결된다. 착용 조건의 조건 번호 1351은 조명 선택 번호 1343을 참조한다. 세 번호를 혼용하면 안 된다.

확인한 연결:

- `0x140a9eeb9..0x140a9eece`: 종류 5를 `0x140ac1cf0`에 전달하고 선택값을 조명 조회 함수 `0x14029e960`에 전달한다.
- `0x140ac1d47..0x140ac1db4`: 캐릭터 상태 `+0x10` 아래 `+0x1a0` 표에서 종류를 찾고 노드 `+0x1c`의 16비트 선택값을 반환한다. 항목이 없으면 `0x140ac1d1e`에서 0을 반환한다. 종류 0용 벡터/순번 경로와 다르다.
- `0x14029e970..0x14029e989`: 선택값으로 조명 템플릿 조회 함수 `0x140e9f830`을 호출하고 템플릿 `+0x29`의 8비트 조명 데이터 번호를 읽는다. `+0x2a`는 이 필드가 아니다.
- `0x140eca726`: 조명 테이블 표를 관리자 `+0xa8`에서 `+0x308`로 교환한다. `0x140e9f830`의 표 머리 `+0x310`과 일치한다. 인접한 `0x140e9f980`은 다른 효과 표이므로 조명 경로로 사용하면 안 된다.
- `0x140a9eed3..0x140a9ef0e`: 조명 조회 실패 시 스킨 값 복사 분기를 건너뛴다. 그 자리에서 착용 조건 테이블을 다시 검색하지 않는다.
- `0x140a6cd88/0x140a80807`도 선택 종류 5의 조명을 읽는다. 이 두 경로는 RGB를 복사하고, 강도는 기존 값보다 클 때만 바꾼다 (`0x140a80833..0x140a80841`). `0x140a9e760` 경로에서는 강도를 직접 복사하므로 모든 경로를 하나의 max 규칙으로 처리할 수 없다.

원본 프로필에 `selection_binding`을 추가하고 프로필 캐시를 버전 7로 올렸다. 원본 스킨 조명 표에서 연결된 항목에만 종류·선택 번호·조명 데이터 번호를 제공한다. 구형 세트 조명과 지역 조명을 현재 스킨 선택값으로 표시하지 않는다. 실행 파일 감사 도구는 기존 열 근거 6곳과 선택 조회·실패·강도 규칙 7곳, 총 13곳을 확인한다.

뷰어의 **선택 상태·착용 조건으로 조명 선택 · 뷰어**를 켜고 **스킨 조명 선택 상태 · 뷰어 지정**에서 다음을 지정한다.

| 상태 | 동작 |
| --- | --- |
| 미지정 | 기존의 단일 착용 조건 후보 추정을 사용한다. 게임 선택값으로 확정하지 않는다. |
| 선택 없음 (0) | 스킨 조명 프로필을 적용하지 않는다. 착용 조건 추정으로 대체하지 않는다. |
| 원본 스킨 조명 선택 | 검증된 선택 번호 연결을 사용한다. 착용 개수·다수 후보보다 명시한 상태를 우선한다. |

지정 상태는 뷰어 설정에 저장한다. 캐릭터가 다르거나 아바타 외 모델·연결 누락·다른 효과 종류라면 적용을 보류하며 다른 조명으로 대체하지 않는다. 수동 비교 선택은 별도로 유지하고 효과 스위치는 변경하지 않는다.

이는 **게임의 실시간 선택값을 가져오는 기능이 아니다**. 장비·보유 조건을 검사해 선택 상태 표를 쓰는 경로, 서버에서 전달되는 값과 잠금 상태, 콘텐츠 활성은 아직 연결하지 않았다. 뷰어에서 선택 상태를 지정하는 것은 비교용 입력이다. 기본 지역 조명과의 합성·경로별 강도 규칙도 아직 렌더러에 반영하지 않았다. 선택 없음은 이 뷰어의 스킨 조명 적용을 중지하는 의미이며 전체 원본 지역 조명이 재현되는 것은 아니다.

브라우저 검사는 실제 툰 uniform으로 명시 선택 우선, 0과 미지정의 차이, 저장 복구, 다른 캐릭터·NPC·다른 효과 종류 거부와 효과 설정 보존을 확인한다. 다음 작업은 원본 지역 기본 조명과 스킨 조명의 합성 경로 구분이다.

## 착용 조건에 따른 뷰어 자동 선택

**선택 상태·착용 조건으로 조명 선택 · 뷰어**를 직접 켜고 선택 상태를 미지정하면 선택 장비의 원본 조건을 충족한 단일 조명을 따른다. 일반 의상 교체, 추가 장비 지정·해제, 눈동자 변경 때 현재 진단 결과로 다시 평가한다. 근사 툰·얼굴·GLOW 등 기존 조명 소비 경로와 같은 선택 함수를 사용한다. 효과 스위치를 자동으로 켜거나 하이퍼 모드 색상을 활성화하지 않는다.

미충족·캐릭터 불일치·정의 누락·다수 후보·경쟁 조건 미검증이면 자동 프로필을 비워 이전 의상의 조명이 남지 않게 한다. 마지막 수동 선택은 별도로 보존하며 자동 선택을 끄면 복구한다. 자동 선택 여부는 사용자 설정에 저장하되 처음에는 꺼져 있다.

게임의 저장된 선택값 자동 가져오기·콘텐츠 활성·선택 상태 결정 규칙은 아직 연결하지 않았다. 위의 후속 기능에서 선택 상태를 직접 지정할 수 있다. `ANIMCHANGE_PRIORITY_TEMPLET.NTF`의 순번이나 `NEW_CONVERT_PACKAGE_TEMPLET.NTF`의 표시 순서를 스킨 조명 우선순위로 추정해 사용하지 않는다. 상태 미지정 시에는 뷰어의 단일 후보 추정을 사용한다.

`test_auto_light_profile_browser.py` 2개는 기본값·저장 복구, 실제 툰 재질 uniform의 색·강도·활성 값, 후보 변경·미충족·중복 우선순위 보류, 수동 선택 복구와 효과 스위치 보존을 검사한다.

## 스킨 조명 연결 열 정정 (2026-10-31)

이전 구현은 별도 enum인 `MCT_LIGHT=4`를 스킨 조명으로 해석하여 10번 열을 읽었다. 잘못된 해석이다. 원본 스킨 enum은 **`SCT_LIGHT=5`**이며 실제 연결은 **12번 열**이다. 로더·레코드 복사·타입별 등록·조명 테이블 등록까지 같은 타입 5로 연결되는 것을 확인했다. 기존 조건·추가 장비 캐시는 버전 2로 올려 잘못된 22행 결과를 재사용하지 않는다.

원본 조명 조건은 6행이다: `(조건, 조명, 개수)`는 `(201,201,10)`, `(203,203,10)`, `(211,211,10)`, `(212,211,10)`, `(1351,1343,7)`, `(1411,1411,7)`이다. 따라서 이전의 “1343·1411은 이 경로에 연결되지 않는다”는 결론도 정정한다. 1343 조명은 조건 **1351**이 참조하므로 같은 번호끼리 맞춰서도 안 된다. 황천의 사자 211·212의 조명 211 연결과 10개 조건은 유지된다.

`tests/audit_light_conditions.py`는 알려진 실행 파일 SHA256과 아래 근거 6곳을 비교한다. 다른 실행 파일은 거절한다. 조건 테스트도 10번 열만 값이 있는 경우와 12번 열만 값이 있는 경우를 분리해 검사한다.

## 별도 착용 장비 연결 (2026-10-31 후속)

일반 모델 목록에서 제외되던 원본 장비를 **추가 장비 착용 지정**으로 조건 계산에 포함한다. `ITEM_TEMPLET*.NTF`의 아이템 번호·캐릭터·장비 유형·착용 부위와 `ITEM_MODEL_TEMPLET*.NTF`의 해당 캐릭터 연결을 검증한다. 일반 3D 모델이 있는 장비나 눈동자 선택으로 다루는 항목은 이 목록에서 제외한다. 같은 장비가 여러 모델 행으로 구성되면 일반 모델이 하나라도 있는 경우 추가 장비로 중복 제공하지 않는다. 이름은 원본 아이템 문자열에서 가져온다.

황천의 사자에서 빠진 두 번호는 다음과 같다.

| 번호 | 원본 명칭 | 착용 부위 | 현재 외형 연결 |
| --- | --- | --- | --- |
| 1499000164 | 황천의 사자 램프 [유니크] | `ACC_BODY_WING` | X 모델 없이 `DE_NETHERWORLD_LAMP_*_SET` 효과로 정의됨 |
| 1799000161 | 황천의 사자 권위 [유니크] | `ACC_RING_RIGHT` | 캐릭터 기본 얼굴·XET와 `DE_RARE_8_AURA_SET_*`에 연결됨 |

두 번호 모두 `ITEM_TEMPLET6.NTF`와 `ITEM_MODEL_TEMPLET.NTF`에 존재한다. 권위는 얼굴에 연결되지만 아이템 정의의 실제 착용 부위는 오른손 반지다. 이를 기본 얼굴로 무시하거나 일반 눈동자로 취급하면 개수가 누락된다. 현재는 사용자가 선택한 장비의 조건 계산만 지원하며, 램프·오라·얼굴 전용 효과의 렌더링을 구현했다는 의미는 아니다.

일반 의상 8개, 램프 포함 9개, 권위 포함 10개, 다시 해제하여 8개로 돌아가는 실제 미래 원본 장면을 검사했다. 같은 장비 번호는 한 번만 세며 동일 부위 중복은 보류한다. 임의 번호·중복 요청·다른 캐릭터·일반 모델 장비의 추가 지정은 서버에서 거절한다. 장비만 변경할 때 `/api/model-lighting-conditions`가 현재 장면과 선택 출처를 다시 검증하고 조건 응답만 반환하므로 뷰어 모델·자세·카메라·텍스처를 다시 만들지 않는다. 선택은 주소의 `condition_items`에 보존하고 같은 장면 재열기와 눈동자 교체에서 유지한다. 새로운 모델을 추가한 의상 선택과 초기화에서는 추가 장비를 다시 지정한다.

별도 눈동자 선택도 원본에서 검증된 `item_id`·`item_ids`·기본 여부와 함께 조건 판정에 전달한다. 같은 외형의 별칭 여러 개를 여러 장비로 세지 않는다. 모든 별칭의 조건 그룹 소속이 같을 때만 0개 또는 1개로 확정하고, 소속이 다르면 확인 보류로 표시한다. 기본 눈동자는 장비 개수에 포함하지 않는다. 별도 메시 눈동자는 일반 모델 경로와 중복 계산하지 않으며 오른손 반지 부위의 충돌도 확인한다.

다음은 게임의 스킨 선택 상태·효과 우선순위·콘텐츠 활성 상태를 연결하여 자동 선택을 확정하는 작업이다. 개수 충족만으로 원본 게임 상태가 모두 재현되었다고 판단하지 않는다.

## 확인한 연결

`NEW_CONVERT_TEMPLET.NTF`의 0부터 시작하는 열 번호:

| 열 | 진단에 쓰는 값 |
| --- | --- |
| 0 | 콘텐츠 버전 태그 — 게임의 활성 상태는 미확인 |
| 1 | 조건 식별자 |
| 2 | 캐릭터 목록 |
| 3 | 추가 조건 — 비어 있지 않으면 선택 보류 |
| 4 | 아이템 그룹 목록 |
| 5 | 필요 개수 |
| 12 | 스킨 조명 연결 대상 (`SCT_LIGHT=5`) — 0이면 이 경로의 조명 연결 없음 |

그룹별 아이템 번호는 `CONVERT_ITEM_GROUP_LIST1/2/3.NTF`의 `(그룹, 아이템)` 관계를 합쳐 읽는다. 파일 이름·의상 이름·타입 표시 문자열로 세트를 추정하지 않는다.

검사한 `CW.EXE` SHA256: `8ea0ce3ba885f3044103c8e071e627b52a0e93cf56cc44b0e03dffed7c440283`.

- `0x141880e4f..0x141880e5e`: `SCT_LIGHT` 이름에 enum **5**를 등록한다. 이름은 `0x1427effa0`에 있다. `MCT_LIGHT=4`는 이와 다른 enum이다.
- 로더 `0x140ec8b60`, 파일 참조 `0x140ec8bc8`: `NEW_CONVERT_TEMPLET.NTF`를 읽는다.
- `0x140ec9479..0x140ec9489`: 열 12의 타입 항목 `[rbx+0x30]`을 로컬 `[rbp+0xc]`에 읽는다. 레코드 시작 `[rbp-0x60]`에 대한 오프셋은 `0x6c`이다.
- 복사 함수 `0x140ea2c5f..0x140ea2c63`: 레코드 `+0x6c`를 보존한다.
- `0x140ec77e6..0x140ec77f3`: 레코드 시작보다 `0x30` 뒤인 `r14`에서 `+0x3c`, 즉 레코드 `+0x6c`를 읽어 타입 **5**의 연결 등록 함수 `0x140ec7050`에 전달한다.
- `0x140ec8321..0x140ec832e`: `LIGHT_CONVERT_TEMPLET.NTF` 레코드도 타입 **5**로 등록한다.
- 조건 식별자와 같은 번호의 조명이 항상 활성화된다고 판단하면 안 된다.

로컬 원본에는 스킨 조명 연결이 있는 행 **6개**가 있다. 황천의 사자 조건 211과 212는 모두 조명 211을 가리키며 필요 개수는 10이다. 아이템 그룹은 각 136개 번호를 포함한다. 일반 스킨 조명 1343·1411은 각각 조건 1351·1411에서 7개 조건으로 연결된다.

## 현재 동작과 한계

서버의 모델 장면 응답에 `lighting_conditions`를 추가했다. 명시적으로 선택한 아이템 번호를 중복 제거하여 센다. 복합 메시·ALPHA와 타입 별칭으로 같은 아이템의 개수가 늘지 않는다. 다른 캐릭터·아바타 외 모델·같은 부위에 여러 아이템·한 벌과 상하의 중복·아이템 출처 누락은 선택을 보류한다. 기본 얼굴은 의상 개수로 세지 않는다.

조명·재질 창의 **조명 착용 조건 확인**에서 개수와 조건 번호를 확인한다. 개수 조건을 충족한 조명이 하나이고 해당 캐릭터의 조명 정의도 하나일 때 **착용 조건에 맞는 조명 선택**을 누를 수 있다. 수동 조명 선택값을 저장하며 툰·광택·기존 색상 비교·하이퍼 모드 등의 켜짐 상태는 바꾸지 않는다. 의상 교체로 조건이 바뀌어도 기존 수동 선택을 덮어쓰지 않는다.

초기 진단에서 실제 미래 황천의 사자 원본 장면의 표시 가능한 8개 아이템은 **8/10, 미충족**이었다. 후속 연결로 위의 추가 장비 두 개를 직접 지정하면 10/10이 된다. 모델이 없는 장비를 표시된 메시 수로 대신 세면 안 된다. 게임의 보유 아이템·선택한 스킨·콘텐츠 활성 상태·효과 우선순위는 이 장면 응답에 없으므로 전체 자동 활성화는 아직 보류한다.

검증: 조건 진단 7개(실제 원본 장면의 추가 장비 선택·해제 포함), 추가 장비·별칭 5개, 조건 UI·장면 연결 브라우저 2개, 기존 눈동자 서버 7개와 장면 브라우저 1개, 조명 파싱·인증·조건 API 5개. 총 27개를 검사한다. 다음은 게임의 선택 상태·우선순위를 확인하는 것이다. 거리·회전 연동, EXT B 계수, 장면별 후처리, 인게임 화면 대조도 남아 있다.
