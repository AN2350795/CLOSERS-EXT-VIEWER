# 표면 법선과 얼굴 음영 기준 검증 (2026-10-31)

하이퍼 모드 색상 효과를 포함하지 않은 조건에서 원본 셰이더와 비교했다. 원본 자료는 읽기만 하며 인게임 화면 일치를 주장하지 않는다.

## 정점 법선 변환 수정

`CW_DEFAULT.VS.CSO`의 스키닝 분기는 정점의 법선·접선·종법선을 뼈 행렬의 3×3 부분으로 변환하고 가중합한 뒤 각각 정규화한다. 비스키닝 분기도 법선을 `g_mWorld`의 3×3 부분으로 직접 변환하고 정규화한다. 이 결과를 정점 출력 `TEXCOORD3`의 법선으로 보낸다. `CW_CARTOONLIGHT.PS.CSO`는 보간된 법선·접선·종법선을 다시 정규화하고 BUMP 방향을 합성한다.

기존 뷰어는 굴곡 경로에서 Three의 `transformedNormal`을 정규화하지 않고 정점 출력에 복사했다. 이 값에는 일반적인 역전치 `normalMatrix` 변환도 적용되어 있었다. 따라서 뼈 가중합으로 정점별 길이가 달라질 때 보간 방향이 원본과 달라지고, 비균일 크기 변형에서도 원본의 직접 행렬 변환과 차이가 있었다.

뷰어의 아바타 굴곡용 법선은 스키닝 후 `objectNormal`을 `modelViewMatrix`로 직접 변환하고 정점마다 정규화하도록 수정했다. 툰·EXT·테두리광이 쓰는 세계 법선도 `modelMatrix`의 직접 변환·정규화를 사용한다. 카메라 변환은 강체 회전이므로 굴곡용 뷰 공간 계산과 원본 세계 법선→뷰 회전의 순서는 같다. 길이가 0인 입력에는 0을 전달한다. Three의 기본 재질 법선 처리 자체와 기본 텍스처는 수정하지 않는다.

`tests/source_normals_checks.js`는 원본 위치·법선과 뼈 변환으로 CPU에서 독립적인 정점 법선·화면 삼각형 무게를 계산한다. GPU 굴곡용 램프와 툰 조회의 픽셀을 일반/4/5 가중치, 균일·비균일 크기, 좌우 반전 조건에서 대조한다. 수정 전에는 예상 193인 채널이 166으로 출력되어 실패했고 수정 후 통과했다. 기존 접선 생성·mip 0·지역 반사·얼굴 음영 검사와 실제 의상 검사도 실행한다. 실제 의상 캡처는 `diagnostics/source-normal-20261031/`에 보관한다.

## 얼굴 좌우·정면 축

`CW_CARTOONLIGHT.PS.CSO`의 얼굴 분기는 `cb3[13:15]`에서 z 성분 세 개를 정면 축으로, y 성분 세 개를 좌우 축으로 구성하고 각각 정규화한다. CPU가 전치해 전달한 `g_matObjWorld`를 Three의 행렬로 대응하면 각각 2번·1번 열이다. 뷰어 `updateAvatarFaceFrame`의 열 선택 순서는 이 부분과 일치한다. 검증 없이 좌우 부호나 축 순서를 바꾸지 않는다.

원본 업로드 `CW.EXE:0x141749ab2~0x141749b1c`의 기준 프레임도 추적해 `BIP01_HEAD`임을 확인했다. `resource+0x88`은 39개 뼈 슬롯 배열의 시작 포인터이며, 그 포인터의 `+0x38`은 8바이트 포인터 7번 슬롯이다. 첫 항목의 객체 필드를 읽는 구조나 첫 SkinWeights의 뼈를 사용하는 구조가 아니다.

| 위치 | 확인한 연결 |
| --- | --- |
| `0x141758ec3~0x141758ef6` | 뼈 이름 표에 `BIP01_HEAD`를 번호 7로 등록 |
| `0x14175149a~0x1417514a6` | 이름 조회 결과의 번호를 프레임 `+0xc8`에 저장 |
| `0x14174e024~0x14174e040` | 프레임을 해당 번호의 `resource+0x88` 슬롯에 등록 |
| `0x141749ab2~0x141749ac7` | SDF 경로에서 배열 `+0x38`, 즉 슬롯 7의 프레임 선택 |
| `0x141749ac9~0x141749ae2` | 프레임 `+0x70~0xa0`의 세계 행렬 로드 |

이 행렬은 스키닝에서도 뼈 세계 행렬로 사용한다(`0x14174960c~0x14174962b`). 뷰어의 고유한 `BIP01_HEAD.matrixWorld` 선택과 좌우 1번·정면 2번 열 추출은 이 경로와 일치한다. 머리 뼈 바인딩 메타데이터를 `source-verified`로 표시하며, 전체 얼굴 미리보기는 툰 강도·게임 후처리 등 미완성 항목 때문에 계속 `approximate`다. 누락·동명이 여러 개인 뼈는 계속 적용을 보류한다.

```powershell
python tests/audit_face_binding.py --exe 'C:/Program Files (x86)/NaddicGames/Closers/CW.EXE'
```

재검사 도구는 조사한 실행 파일 SHA256과 이름·번호·슬롯 기록·슬롯 선택·행렬 조회 등 근거 바이트 7곳을 확인한다. 다른 실행 파일은 주소 근거를 적용하지 않고 실패한다. 원본 게임을 실행하지 않으며 기록은 `diagnostics/face-binding-20261031.json`에 보관한다. 이 바인딩 검증은 장면별 전체 변환·조명과 인게임 최종 화면의 일치 검증을 대신하지 않는다.

## 원본 접선 생성 경로 확인과 적용

`CW.EXE:0x141750980~0x1417509c1`은 보조 텍스처 type 4(BUMP)가 있는 메시에서 `0x141745f80`을 호출한다. 이 함수는 정점 stride `0x64`, 위치 `+0`, UV `+0x24/+0x28`, 법선 `+0x40`, 접선 `+0x4c`, 종법선 `+0x58`을 사용한다. 원본 삼각형 세 정점의 위치·UV 차이에서 다음 미분 방향을 만들고 세 정점에 같은 값을 누적한다.

```text
det = du1*dv2 - du2*dv1
Tface = (edge1*dv2 - edge2*dv1) / det
Bface = (edge2*du1 - edge1*du2) / det
Tvertex = normalize(sum(Tface) / incidentCount)
Bvertex = normalize(sum(Bface) / incidentCount)
if dot(cross(Nvertex, Tvertex), Bvertex) < 0: Bvertex = -Bvertex
```

삼각형 미분 계산은 `0x141746050~0x14174627d`, 정점별 누적·개수는 `0x141745da0~0x141745f76`, 평균·개별 정규화는 `0x141746410~0x141746528`, 종법선 부호 보정은 `0x14173da40~0x14173db75`다. 접선을 법선에 투영하여 직교화하거나 종법선을 외적으로 새로 만들지 않는다. 이 차이로 비스듬한 UV·매끄러운 법선·대칭 UV에서 이전 Three `computeTangents`와 다른 방향이 나온다.

`model-tangents.js`를 위 방식으로 수정했다. 평균 후 정규화와 합 후 정규화의 방향은 같으므로 합을 정규화한다. 원본 위치·법선·UV·면·스킨 가중치는 유지하며 UV가 퇴화했거나 계산이 유효하지 않은 삼각형은 주변 정점을 오염시키지 않도록 제외한다. 유효한 축이 없으면 기존 미분/정점 법선 fallback을 사용한다. 원본의 무효 수치까지 재현하거나, X 로더의 정점 분리·병합을 포함한 바이트 단위 일치를 주장하지 않는다.

GPU 기준 검사는 기존 직교화 경로에서 실패하고 수정 후 통과했다. 한 삼각형의 독립 미분값, 두 인접 삼각형의 서로 다른 미분값 누적, 종법선의 별도 평균, 대칭 UV 부호·모델 반전·일반/4/5 가중치·퇴화 UV·OFF 복원을 대조한다. 실제 바니 의상과 반사 지수가 있는 오로라 픽시즈도 검사하며 캡처는 `diagnostics/source-tangents-20261031/`에 보관한다.

## 얼굴 SDF alpha의 mip 0 고정

원본 `CW_CARTOONLIGHT.PS.CSO`는 좌우 반전 UV와 일반 UV에서 얼굴 alpha를 각각 `sample_l(..., 0)`으로 읽는다. 기존 뷰어의 `texture2D`는 자동으로 낮은 mip을 선택하므로, 같은 얼굴이라도 화면에서 작아지면 SDF 임계값이 달라질 수 있었다. 두 alpha 조회를 모두 `textureLod(..., 0.0)`으로 수정했다. 기본색 RGB의 mip 선택과 눈·다른 재질, 얼굴의 불투명도는 유지한다.

`tests/face_basis_lod_checks.js`는 mip 0의 alpha가 0, 낮은 mip의 alpha가 1인 텍스처를 사용하여 일반/4/5 가중치·32/96픽셀에서 자동 mip의 오류를 드러낸다. 수정 전 실패, 수정 후 통과를 확인했다. 별도 중간 alpha 텍스처로 부모의 ±90도 회전·이동과 머리의 비균일 크기 변형을 적용하여 정면 축 방향과 명암 식도 독립적으로 대조했다. 이 GPU 검사는 축 추출을 검증하며, 프레임 이름·슬롯 선택은 위 정적 바인딩 감사로 별도 확인한다.

기존 얼굴 SDF의 좌우 UV·눈 제외·불투명도·OFF 복원·발광 분리와 원본 이슬비/서유리/루시/애리 얼굴 및 이슬비 공통 동작도 대조했다. 원본 캐릭터 식별자는 CASTER/STRIKER/DEVILISH/GATEKEEPER이며 실제 캡처는 `diagnostics/face-basis-20261031/`에 보관한다. 하이퍼 모드 효과는 사용하지 않는다.
