# 원본 DOF 경로와 적용 조건

2026-11-01. 원본 DOF(피사계 심도)의 깊이 입력·흐림·합성과 활성화 경로를 읽기 전용으로 조사했다. 감사 도구와 계산식 검증에 이어 뷰어의 **깊이 출력·사전 흐림·8지점 합성**을 구현하고 수동 심도 비교 메뉴에 연결했다. 기본값은 꺼짐이며 게임의 실시간 초점 설정은 연결하지 않는다.

## 확인한 구성

| 단계 | 확인한 내용 |
| --- | --- |
| 깊이 기록 | 아바타 VS의 뷰 좌표 Z를 PS에서 초점 기준으로 변환해 색상 MRT2의 RGB에 기록 |
| 사전 흐림 | 모드 3, 기법 13/14. 가로·세로 9개 샘플이며 첫 가로 패스의 알파에 원본 MRT2의 R을 기록 |
| 최종 합성 | 기법 15, `CW_DepthOfField.PS.cso`. 원본 색·흐린 색·인코딩된 깊이를 8개 지점에서 읽고 깊이 가중 합성 |
| 실행 순서 | Glow → Edge → DOF → 다른 조건부 패스 → ColorGrading |
| 알파 | 원본 DOF의 일반 출력은 1. 뷰어의 투명 배경 유지와 다름 |

깊이 입력은 하드웨어 깊이 버퍼를 그대로 읽은 값이 아니다. [앞서 확인한 타깃 배열](AVATAR_BLOOM.md)의 SRV `+0x1b0`은 슬롯 2인 MRT2에 해당한다. 최종 합성의 원본 색은 SRV `+0x1a0`, 흐린 색은 세로 타깃 배열의 두 번째 항목에서 읽는다. 모든 흐림 단계를 평균하는 번짐 합성과 구분한다.

## 활성화와 계수

- 후처리 객체 `+0x290`의 **비트 2**가 최종 DOF 호출과 초점 상수 업로드를 제어한다.
- 확인한 설정 적용 경로는 `+0x182` 바이트를 **정확히 1과 비교**해 비트를 켜거나 끈다. 별도 제한 경로는 이 바이트를 0으로 덮어쓴다. 실제 실행 중 선택 상태는 읽지 않았다.
- 프리셋 표의 범주 5·열 6은 기존 조사대로 심도 활성 입력이다. 프리셋 4·6은 꺼짐이다. 이 표 값과 실제 실행 플래그 사이의 모든 선택·덮어쓰기 경로가 연결됐다는 뜻은 아니다.
- 초점 데이터는 현재 키로 조회하고 실패하면 키 0을 조회한다. 현재 캐릭터나 지역 이름으로 키를 추측하지 않는다.
- 조회된 float 벡터의 0~3번은 `CBPerGlobal[8]`로 복사된다. 4번, 4번×2, 6번은 `CBPerPostProcess[27].xyz`로 복사된다. 조사한 populated 업로드 구간에서는 `.w`를 쓰지 않는다.
- 데이터가 없으면 두 상수를 0으로 쓴다. 이것을 안전한 중립 DOF 설정으로 취급하지 않는다. 셰이더 식에는 나눗셈이 있다.

`GRAPHIC_OPTION_DATA_DETAIL.NTF` 범주 2의 **열 5~12 수치 8개를 순서대로 복사**하고 DOF 객체의 맵에 등록하는 경로를 확인했다. 기본 행의 벡터는 `[0,0,6000,0.5,0.5,1,0,0]`이며 이 업로드 구간에서 생성되는 후처리 xyz는 `[0.5,1,0]`이다. 이 값으로 뷰어의 초점을 자동 설정하지 않는다.

조회 키는 행 식별자(열 1)가 아니라 **열 4 토큰을 enum으로 변환한 값**이다. 기본 행의 식별자는 0, 토큰은 `WI_INVALID`이며 enum 숫자값은 이 감사에서 확정하지 않았다. 이전 진단 JSON의 `key`는 행 식별자를 기록했으므로 현재 `row_id`로 정정하고 `runtime_key_token`·`runtime_key_numeric`을 분리했다. 번짐 감사의 같은 메타데이터도 정정했다. 실행 경로의 키 0 fallback과 표의 행 식별자 0을 같은 의미로 취급하지 않는다.

## 깊이 인코딩

조사한 `CW_Default.VS/PS.cso`에서 뷰 좌표 Z를 `z`, `CBPerGlobal[8]`을 `[N,F,R,C]`로 표기한다. N/F/R은 수식상의 근거리 기준·초점·원거리 기준을 뜻하며 실제 단위나 라이브 카메라 값의 연결을 보장하지 않는다.

```text
z < F:  signed = (z-F)/(F-N)
그 외: signed = min(max((z-F)/(R-F), 0), C)
MRT2.rgb = 0.5*signed + 0.5
```

근거리 식에는 별도 포화 연산이 없다. 이후 UNORM 타깃 저장에서 범위를 벗어난 값이 잘리고 양자화된다. 초점 위치의 수식 결과 0.5도 UNORM8에서는 약 128/255가 된다. MRT2 알파는 재질의 별도 처리 대상이므로 위 식으로 대체하지 않는다.

`dof_reference.depth_encoding()`은 이 RGB 계산과 근사 UNORM8 값을 기록한다. 사용되지 않는 반대쪽 분모가 0이라는 이유로 유효한 분기를 막지는 않으며, 실제 선택한 분모가 0이거나 역전됐으면 거부한다. 중립값을 만들어 넣지 않는다.

## 최종 8지점 합성

깊이 R을 d, `CBPerPostProcess[27]`을 P, `[25].xy`를 S라고 하면 다음 반경을 사용한다.

```text
signed = d*P.y - P.x
세밀한 샘플 오프셋 = disc[i] * abs(signed) / S
흐린 샘플 오프셋 = disc[i] * abs(signed) * P.z * 2 / S
```

첫 지점은 중심 (0,0)이고 나머지는 원본 DXBC의 고정 방향 7개이다. 공유 흐림 경로도 S를 갱신하지만, 최종 DOF 합성 직전 `0x141571e08~0x141571e3a`에서 **현재 DOF 입력 타깃의 실제 너비·높이**로 다시 기록하고 z/w를 0으로 설정한다. 마지막 축소 흐림 타깃 크기가 그대로 남는 것은 아니다. `dof_reference` 함수는 검증자가 전달한 S를 명시적으로 사용하며 임의의 화면 크기를 가정하지 않는다.

각 지점에서 원본 RGB와 그 지점의 인코딩 깊이를 읽고, `abs(2*depth-1)`로 원본/흐린 RGBA를 섞는다. 섞인 깊이가 중심 깊이보다 크거나 같으면 가중치 1, 작으면 `abs(2*mixedDepth-1)`를 쓴다. RGB 가중 합을 총 가중치로 나눈 뒤 **알파 1**을 출력한다. 단순 Gaussian 또는 거리별 흐림 배율만으로 이 전체 식을 대신할 수 없다.

P.w가 양수이면 일반 합성 대신 진단 색상을 표시하는 분기가 있다. 근거리 쪽은 녹색, 원거리 쪽은 파란색을 강조한다. 이는 보기 좋게 만드는 색상 효과가 아니므로 일반 표시 옵션으로 제공하지 않는다.

`dof_reference.sampling_offsets()`와 `gather()`는 수식을 독립적으로 검증하기 위한 분석 코드다. 실제 텍스처·카메라 상태를 가져오지 않고 Python 실수 계산을 사용한다. 원본 float32·샘플러·래스터화·블렌딩의 비트 단위 재현은 아니다.

## 뷰어 깊이 출력 GPU 패스

`web/model-dof-depth.js`의 `createDofDepthPass()`는 기존 뷰어 모델에 명시적인 초점 상수 4개를 주어 깊이 RGB를 UNORM8 타깃에 출력한다. 심도 비교가 유효할 때 호출하며 자동으로 효과를 켜지 않는다.

- Three.js의 뷰 좌표 `-mvPosition.z`를 양의 전방 거리로 사용한다. 모델/스킨 변형이 끝난 뒤 계산하며 게임 카메라 상태와 자동 동기화한 값은 아니다.
- 일반 MeshBasicMaterial의 기존 알파 테스트를 유지하여 뚫린 텍스처 영역을 보존한다. 가산 블렌딩이나 깊이 검사/쓰기 해제 재질은 지원하지 않고 거부한다.
- 모델 외의 바닥·격자·장면 내용은 제외한다. 표시 중인 불투명 보조 모델은 깊이 버퍼에만 먼저 그려 뒤에 가려진 아바타의 커버리지를 제외한다. 보조 모델 자체의 DOF 깊이를 생성하지는 않는다. 진단용 빈 픽셀은 초점 중립 RGB 0.5 / 커버리지 알파 0, 그려진 아바타는 알파 1이다. 이것을 원본 MRT2 알파 재현으로 간주하지 않는다.
- GPU 입력은 `근거리 < 초점 < 원거리`, 원거리 제한 0~1의 명시적인 유효값만 받는다. N=F인 원본 기본 행을 그대로 가져와 보정하거나 자동 적용하지 않는다.
- 일반 표시·색공간·렌더 타깃·배경·clear 값·autoClear와 임시 재질 플래그를 유지/복원한다. 렌더 오류 중에도 복원한다. 재질의 깊이 훅은 이후 비활성 상태로 유지되며 모델 재질이 해제될 때 함께 정리된다.

GPU 테스트에서는 근거리·초점·원거리 출력 32/128/191을 독립 계산과 대조했다. 기존 정상 화면이 훅 추가 뒤에도 같고, 5개 뼈 가중치에 따른 깊이 변화·알파 구멍·반투명 기본 재질·장면 격리·크기 변경·오류 복원이 동작하는지 확인했다. 이 깊이를 아래 수동 DOF 비교의 입력으로 사용한다.

## 수동 심도 비교

조명·재질 → 화면 효과 → **초점 밖 흐림**에서 사용한다. 아바타와 원본 형식의 색상 계산이 필요하다. 기본은 꺼짐이며 초점 거리·범위는 빈 값이다. `현재 모델에 초점 맞추기`는 현재 카메라의 전방 방향으로 표시 중인 모델의 경계 중심까지 거리를 계산하고, 경계 대각선의 1/4(최소 초점 거리의 1%, 0.01)을 범위로 입력한다. 버튼은 효과를 켜거나 다른 설정을 바꾸지 않는다. 이후 카메라 이동에 자동 추종하지 않는다.

`measureDofFocus()`는 클릭 시 현재 월드 변환과 스킨 자세를 갱신하고, 모델 루트에 속한 표시 메시에서 실제 그리기 범위의 삼각형 정점만 읽는다. 숨긴 장비·상위 그룹·재질, 카메라 레이어가 다른 메시, 분리된 메시, 그리지 않는 재질 그룹·정점과 사용하지 않는 뼈는 제외한다. 5개 이상의 뼈 가중치도 기존 CPU 스킨 계산을 그대로 따른다. 표시할 삼각형이 없거나 유효한 전방 초점 거리를 구할 수 없으면 기존 입력값·저장값을 유지하고 상태 문구로 안내한다. 이는 그릴 형상의 경계이며 텍스처 알파 구멍·다른 물체에 의한 가림·화면 가장자리 클리핑까지 픽셀별로 판정하는 자동 초점은 아니다.

- 초점 벡터는 `[max(0, 거리-범위), 거리, 거리+범위, 0.5]`이다. 두 값은 양수·유한값만 받으며 유효하지 않으면 적용을 보류한다.
- `model-dof.js`는 1/2·1/4 크기의 가로/세로 UNORM8 9지점 사전 흐림을 만들고, 원본 합성이 사용하는 두 번째 세로 흐림을 읽는다. 가중치는 원본의 sigma 1 Gaussian이며 정규화하지 않는다. 첫 가로 패스에 깊이 R을 알파로 넣는다.
- 합성 식의 P는 수동 비교용 `[0.5, 1, 1, 0]`으로 고정한다. 원본 기본 벡터에서 확인한 P.z=0과 다르며, 현재 게임 프리셋을 복원한 수치로 표시하지 않는다. 샘플 방향은 원본 명령 목록에 표시된 소수 6자리 값이다.
- 최종 입력 크기는 전체 화면 크기다. 처리 순서는 번짐 → 선명도 → 심도 → 색상 보정이다. 효과 강도 0~1로 원본 RGB와 혼합한다.
- 뷰어 차이: 원본의 알파 1 대신 기존 화면 알파를 보존하고, 모델이 없는 픽셀은 기존 화면을 유지한다. 가중치 합이 0이면 기존 RGB로 복귀한다. 파랑·초록 진단 색상은 사용하지 않는다.
- 모델이 없거나 미지원 재질이면 적용하지 않는다. 발광만 보기·광택 범위 진단에서는 잠시 보류하고 선택값을 유지한다. 설정은 `closers-avatar-lighting-v2`의 `dofVersion:1`로 저장한다.

GPU 검사는 독립 CPU bilinear/clamp 및 매 단계 UNORM8 계산과 강도 0/0.45/1을 대조한다(채널 오차 최대 2). 전체 렌더러의 DOF 단독 실행, 알파 보존, 비활성 복원, 선명도·색상 보정 병용, 깊이 오류 후 상태 복원, 메뉴 기본값·저장 복원·수동 초점·진단 보류도 확인한다. 실제 인게임 프레임과의 일치를 증명하는 검사는 아니다.

## 재검증과 결과

### 모델 교체·비동기 로딩과 종료

2026-11-02 실제 앱 모듈에서 색상 보정·선명도·심도·5단계 번짐을 선택한 상태의 모델 교체와 비동기 응답 순서를 검사했다. 교체 실패 시 기존 화면 유지, 취소된 모델·텍스처의 늦은 완료, 디코딩 중 종료, 종료 후 새 요청과 큐에 남은 크기 변경, 반복 종료와 설정값 보존이 통과했다. 종료 시 남아 있던 viewport 감시자를 해제하고, 닫힌 뷰어가 새 모델을 받지 않도록 수정했다. [검사 조건·재검증 방법](AVATAR_PERFORMANCE.md)을 참고한다.

### GPU 자원과 종료 수명 관리

2026-11-02 `test_postprocess_lifecycle_browser.py`에서 후처리 생성·종료를 3회 반복하고, 65×49·96×64·31×29·3×3 화면에서 11가지 효과/발광 설정을 전환하며 **693프레임**을 검사했다. 작은 화면의 5단계 번짐·심도 보류 경로도 포함한다. 매번 워밍업에서 저장한 RGBA와 정확히 일치하는지 확인하고, 별도로 3회 외부 렌더 타깃·clear 값·autoClear 보존을 검사한다.

- WebGL의 생성·삭제 API를 계측해 Texture·Framebuffer·Renderbuffer·Buffer·VertexArray·Program·Shader 핸들의 생존 수를 비교한다. Three.js의 텍스처·기하·프로그램 카운터도 함께 확인한다.
- 각 크기와 기능을 워밍업한 뒤 반복 전환·리사이즈해도 생존 수가 증가하지 않았으며, 모델·텍스처·후처리 종료 후 각 생성 주기의 초기 수로 복귀했다. 내부 렌더 타깃 25개가 모두 실제 렌더 경로에서 사용되고 한 번씩 해제되는지 확인한다.
- 반복 종료에서 같은 타깃의 해제 이벤트가 다시 발생하던 문제를 수정했다. 전체 후처리와 5단계 번짐 보조 모듈의 `dispose()`는 여러 번 호출해도 한 번만 해제한다. 종료 후 렌더/크기 변경 요청은 GPU 자원을 다시 만들기 전에 거부한다.
- 뷰어가 열려 있는 동안에는 재사용을 위해 비활성 효과의 타깃도 캐시한다. 효과를 끌 때마다 모든 캐시를 없애는 방식은 아니며, 테스트 역시 워밍업 이후의 안정성과 최종 해제를 구분한다.

이 검사는 WebGL 핸들·렌더러 카운터 기준이다. 드라이버의 지연 해제나 실제 VRAM 바이트·브라우저 전체 메모리 사용량을 측정한 것은 아니다. 메뉴나 저장 설정은 변경하지 않는다.

`test_postprocess_order_browser.py`는 전체 `createEmissionRenderer` 경로를 독립 CPU 이미지 계산과 대조한다. 두 화면 크기(45×33, 51×37), 번짐 꺼짐·기본 번짐·5단계 번짐, 세 효과의 8가지 켜짐 조합, 동시 적용 시 심도 강도 0/1과 최종 sRGB 출력까지 **66개 조합**을 검사한다. 검증한 순서는 **번짐 → 선명도 → 심도 → 색상 보정 → 최종 색 변환**이다.

### 강한 발광과 효과 전환의 밝기 제한

2026-11-02 `test_postprocess_hdr_browser.py`에서 발광 강도 0.5/1/4와 번짐 꺼짐·기본 번짐·5단계 번짐을 조합했다. 일정한 색의 평면을 사용해 기본색·발광·번짐 합성을 해석적으로 계산하고, **RGB 제한 → UNORM8 저장 → 색상 보정 → 최종 색 변환** 결과를 비교한다. 이전 66개 순서 검사처럼 이미 제한된 화면에서 HDR 입력을 추정하지 않는다.

## 다음 작업

2026-11-04 후속 점검에서 여러 변환 그룹·던전/마을이 공유하는 클립은 모든 원본 문맥에서 동일한 공통 연출만 복구하도록 개선했다. 세하 레어 2 공유 달리기의 발밑 먼지를 실제 원본과 브라우저에서 확인했다. 상세 범위와 계속 보류하는 항목은 [공유 클립 검사](PARTICLE_DEPTH.md)에 기록했다. 이 변경은 연출 연결 개선이며 파티클의 심도 지원 종류를 확장하지 않는다.

수동 심도 비교·현재 자세 기반 초점 계산·실제 의상의 광택 병용·후처리 조합과 GPU 자원 검사를 완료했다. 모델 교체·보조 효과 지연 로딩 취소·종료에서도 상태 복원과 자원 해제를 확인했다. 불투명 보조 모델의 가림을 번짐·심도에 반영하며 알파 테스트 구멍·뒤쪽/숨긴 모델·깊이 미기록 모델·가산 파티클을 구분한다. 각 검사의 조건과 한계는 위 검증 항목에 기록했다.

반투명·가산 파티클의 [깊이 조사](PARTICLE_DEPTH.md)에서 원본 출력·Lua 설정·일반 평면의 QUAD 선택·블렌딩·깊이 상태를 확인했다. 공유 플래그 초기화·복원·상수 버퍼 업로드·타깃 연결을 명령 바이트 38곳과 실제 셰이더 RDEF 메타데이터로 대조했다. 별도 RGB/MRT2 패스의 GPU 비교 131개 조건·786개 픽셀 비교도 통과했다. 이 초기 조사에서는 파티클 DOF를 추가하지 않았으며, 이후 호출 경로 확인과 아래의 일반 평면 구현으로 이어졌다.

실제 장면의 활성/덮어쓰기·모든 MRT2 기여·재질별 깊이/블렌딩과 인게임 프레임 대조는 남아 있다. 번짐의 특수 효과와 게임 상태 연결도 별도 과제다.
